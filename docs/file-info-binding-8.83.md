# Prepared media binding: 8.83 / browser 0.72.47

## Presentation boundary

A media admission can finish before its prepared-view notification reaches Main. Previously that case fell back to ordinary browser presentation: restore the job, inspect presentation state and recapture File Info on the window thread. The prepared route now handles that already-accepted case as well as still-pending admission. It renders the owned media view immediately and binds its job using an owned reader.

The reader verifies current membership, Awaiting confirmation status, absence of an individual Start, protocol/status/job/fingerprint receipt identity, the outstanding download presentation and equality with a fresh File Info view. Changed selection/display inputs fail closed while retaining the draft. The read is not an admission or Start authority and performs no persistence or session attachment. UI attachment still loses to a prior Cancel, and a result for a superseded retry operation cannot bind the older job.

The worker uses cancellable model-lock acquisition. Closing a pending window wakes and joins a reader waiting for another model owner, rather than making teardown wait for that external owner. Work already reading its bounded snapshot remains joined. Only owned integer notifications reach the Form; no worker touches controls. Other accepted commands defer binding, and timer cadence retries that read without a completion-driven loop.

Binding also captures the grouped presentation tokens it actually checked. Acknowledgement after the dialog acts on that captured offer; a later capture remains pending. Pending cancellation keeps the existing receipt-bound cancellation worker. Regular decisions, prefetch admission, final publication and destination validation retain their authoritative backend paths.

This increment covers prepared, non-form media admission. Legacy/direct/form initial preparation, post-dialog presentation acknowledgement and other explicit/fallback reads still have synchronous paths. Receipt validation is deliberately retained; a render cache alone does not prove acceptance. There is no claim of full IDM parity, universal initial latency or personal-browser acceptance.
