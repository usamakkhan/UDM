# Time Left estimates and ordering, UDM 1.28.0

UDM's duration-based media ETA previously stopped at 86,400 seconds, even when current-attempt coverage implied several days remaining. Byte ETA cast the quotient directly to int64, allowing an out-of-range cast at extremely small positive finite rates. The traced reference ETA callback has no one-day calculation cap and uses separate display and comparison rules.

The shared calculator now retains the full duration-derived estimate, excluding restored coverage through StreamResumedMs and using only progress made during the current attempt. It validates coverage/baseline bounds and finite positive elapsed time. Both byte and media estimates pass through a guarded nonnegative integer conversion. Positive overflow saturates at INT64_MAX before any cast; invalid/unknown inputs return -1. The remaining-byte subtraction is performed only after validating received bytes against a positive size. Exact full coverage returns zero while the record is still Downloading. Live and inactive transfers remain unknown. Existing stored metadata is not changed.

Main-list and Scheduler Time Left cells now have a separate wrapper: floor the positive finite byte rate and require it to exceed 10 B/s before displaying an estimate. The reference list-insertion assembly checks its integer speed field against 0x0a, divides remaining bytes by that integer and formats the result. Progress dialogs continue using the shared fractional-rate calculator without this list-only threshold. Duration ETA still uses elapsed/current-attempt coverage, rather than deriving timeline progress from received bytes.

Time Left sort keys are prepared once per row outside the manager lock. The reference's ascending callback uses numeric remaining seconds, defaults unavailable estimates to zero and puts completed records first on equal ETA; its descending wrapper negates that result. UDM now follows that ordering and includes both seconds and completion in cache validation. Sorting keeps integer-rate estimates even below the cell-display threshold. Unknown and genuinely zero estimates therefore share the numeric key, while the stored completion flag resolves that tie. Other equal keys retain catalog order. UDM does not invent a retained inactive-transfer rate: exact reference cached-rate behavior on paused/recovered transfers remains unverified.

The reference time formatter accepts hours through 10,000 and writes a single-space literal above that limit. UDM now uses that same display bound; estimates remain uncapped by it internally for sorting and progress calculation. Existing sec/min/hour wording is retained. Saturating modern floating-point overflow is a UDM safety rule, not a claim about reference integer overflow behavior. Floating-point precision, clock mapping and the mapping from UDM's measured double rate to IDM's internal integer fields still need runtime qualification.

Existing MenuStateTests assertions were maintained for the prior reference Status score/locale changes and the new low-rate cell contract. MediaChecks includes deferred cases for estimates beyond one day, extreme finite rates, zero remaining bytes and list/progress threshold separation. These sources were not compiled or executed. See [reference trace](reference/idm-time-left-20261104.json) and [build receipt](validation/idm-time-left-build-20261104.json). Runtime tests, installer creation, installation and publication remain deferred. Full IDM parity is incomplete.

All five production executables built successfully at 1.28.0. Product versions, executable hashes and unchanged feature-source hashes were verified in the receipt. Test sources were not compiled or executed, and runtime behavior remains unverified.
