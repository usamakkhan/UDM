# MP4 WebVTT edit sequences

The single-edit implementation is extended to bounded sequences of up to 64 elst entries in version 0 or 1. Normal-rate media edits may repeat or reorder media intervals. Empty edits use signed media_time -1 and advance the movie clock without emitting cues. Other negative values, dwell/speed-changing rates, malformed counts, more than seven days of cumulative movie duration, and zero-duration entries before the final media edit remain rejected. A final zero-duration media edit supplies an open-ended fragment offset.

Each cue is intersected with each media edit. Differences are calculated in integer media ticks before conversion, avoiding cancellation between large composition times and media starts. Finite durations are first rounded up to a media tick to bound input; the final boundary is independently calculated from movie units. Movie placement and DASH PTO are included in the same millisecond conversion. Empty intervals remain gaps. Repeated sections copy cue text, settings and identifiers; a stable sort restores movie-time order. Existing 100,000-cue and 16 MiB text budgets count expanded output, and cancellation is checked during emission. Fragment decode continuity remains independent of presentation edits.

This follows the movie/media timescale distinction and repeated-section model in [Apple's edit-list documentation](https://developer.apple.com/documentation/quicktime-file-format/playing_with_edit_lists). [DASH-IF timing](https://dashif.org/Guidelines-TimingModel/) places edits before the DASH presentation mapping. The [single-edit MSE contract](https://www.w3.org/TR/mse-byte-stream-format-isobmff/) remains supported. These sources establish container semantics, not observed IDM behavior for these exact caption cases.
