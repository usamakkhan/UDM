# Remote ZIP preview cancellation — UDM 1.53.0

Source inspection found that ZipPreviewTask captured its owning task pointer and joined its network thread in stop/destruction. The dialog's Cancel and close paths called stop on the UI thread. A blocked HTTP/FTP, resolver, proxy or operating-system call could therefore keep that dialog from closing even after the cancellation flag was set. The local preview already used independent state and nonjoining cancellation; this increment addresses the separate remote path. It is a UDM source finding, not a fresh IDM private implementation observation.

Remote preview now captures shared cancellation/result state, owned request/preferences and a worker slot. It does not retain a task-this pointer, dialog, HWND or raw Manager reference. Stop only sets the shared atomic cancellation flag. A snapshot after stop reports Cancelled immediately. While work remains Checking, an expired deadline reports the existing timeout error without waiting for a blocked call to return. The worker rechecks cancellation/deadline before publishing, so a later result cannot replace cancellation with Ready. Immutable listings remain shared with the virtual list.

At most four remote preview workers can be outstanding per process. A fifth task returns an explicit previous-previews-still-closing error rather than starting another thread. Slots release on worker completion and thread-creation failure. The local file-preview pool is separate. This does not forcibly abort synchronous operating-system calls: canceled/timed-out workers retain their owned request/session data until those calls return or the process ends. Four stuck calls can exhaust the remote pool; no unbounded replacement workers are created.

Detaching the original callback was unsafe because browserSessionSaver captured Manager by reference. That helper now delegates to a Manager-owned callback factory. Each callback captures shared lifetime state, JobPtr and its expected browser session. It briefly acquires a lease under a dedicated mutex, releases that mutex, then takes the ordinary Manager lock to validate and persist the rotated session. The lifetime mutex is never held while waiting for the catalog lock or performing disk IO, avoiding a new opposing lock order for callers already holding the recursive Manager lock.

Manager destruction nulls the lifetime owner before waiting for active leases to drain, outside its catalog lock. A later callback cannot dereference the destroyed manager. A callback already using it finishes before member destruction. The existing owned periodic checkpoint worker remains the last member and retains its shutdown ordering. Ordinary stop sets stopping, and callbacks reject session writes while that flag is set; if the final save fails and the app resumes, new valid callbacks can use the still-live manager. The factory does not capture a window or preview task.

Session persistence still verifies catalog membership and the expected currently saved session, so removal or newer browser recapture cannot be overwritten. It saves the protected rotated session synchronously and restores the previous protected value on failure. The expected session advances only after success, matching the prior request-pool serialization contract. Preview persistence checks cancellation before invoking its supplied callback. A cancellation racing with a callback already underway can still allow that in-flight save to finish; no rollback of a successfully committed rotation is claimed. Manager destruction and ordinary catalog access can wait for that save, so this does not eliminate all UI/shutdown waits.

All production remote-preview callers use the guarded browserSessionSaver helper. The C++ task still accepts an optional custom callback; its contract now explicitly requires ownership-safe captured state. The guard cannot make an arbitrary externally supplied raw-reference callback safe. The existing offline fixture's final job/path snapshot was moved under Manager lock because stop no longer establishes a worker-join synchronization point. That fixture was maintained but not compiled or run.

ZIP parser bounds, URL/auth/session scope, byte-range/size/validator verification, read budget, virtual listing, no-extraction policy and transfer byte accounting are unchanged. The related DownloadPreview metadata task still joins on stop; it was not detached in this increment. There is no runtime latency, network cancellation, session race, blocked-callback, pool-limit or shutdown proof.

All five production native targets built successfully with exit code 0 and report 1.53.0. Captured source hashes remained unchanged; executable sizes and SHA-256 hashes are recorded in the receipt. Compilation does not establish runtime behavior. Browser source remains 0.63.85. Runtime tests, installer creation, installation and publication remain deferred. Full IDM parity remains unfinished.
