# Mixed-selection removal — UDM 1.45.0

The retained IDM list keyboard handler at 0x00489860 dispatches Delete to 0x00470380, Ctrl+A to list selection, Ctrl+F to Find, Ctrl+M to the move worker and F3 to Find Next. Those five UDM actions were already present. The checked PE has no RT_ACCELERATOR resource; that does not rule out dynamically created accelerators or other key handlers. No new speculative shortcuts were added. The [official main-window help](https://www.internetdownloadmanager.com/support/main.html) describes removal and incomplete-download confirmation, while the specimen provides the more detailed mixed-selection flow below.

At 0x00470380 the reference first detects completed records (state 3) and counts eligible incomplete records separately. It consults bNShConfDelFrLstDlg before the completed dialog and bNShConfDelUncDlg before the unfinished dialog. Declining the completed dialog returns immediately. Declining the unfinished dialog returns only when no completed group exists; otherwise it clears a flag used by the removal loop to preserve unfinished records. The final iteration follows selected-row order. These are static control-flow findings, not an executed deletion experiment.

The language table contains separate unfinished messages for a mixed selection, one unfinished download and multiple unfinished downloads at 0x006b2758, 0x006b27d8 and 0x006b2840. The caller chooses the mixed form whenever a completed group exists. UDM now uses those variants with UDM branding and retains its existing dialog geometry, default No action, completed-file recycle option and suppression checkbox behavior.

UDM previously reduced the selection to one any-completed flag. A mixed selection therefore used only the completed dialog and one approval for both groups. The workflow now captures each record's original completion class and the group counts before showing either dialog. Completed approval comes first; unfinished approval is separate. No on the completed group aborts. No on a pure unfinished selection aborts. No on the unfinished part of a mixed selection leaves that part in the catalog and processes the approved completed records in original selection order.

SkipCompletedRemovalConfirmation and SkipIncompleteRemovalConfirmation remain independent. Each nonempty group reads its own preference, and accepted suppression choices are saved together using current settings after the approved removals. Choosing Recycle Bin applies only to approved completed records and cannot be remembered as automatic file deletion. Unfinished records never inherit the other group's recycle choice. Existing custom three-argument confirmation/recycle callback signatures remain usable; production default confirmation additionally receives count/mixed context.

The UI checks completion class again before acting. Manager::remove also accepts an optional expected completion class and validates it after scoped file/replacement recovery while holding the manager lock, before erasing the catalog record. A changed or removed record stops that removal for review. Existing one-argument callers retain their default behavior. Active-transfer rejection, pending replacement dependencies, selected-tree recovery and catalog-save rollback remain. These protections are UDM's established recovery policy, not a claim that its private state model is identical to IDM's.

Removal remains sequential rather than all-or-nothing: a later error can follow earlier approved removals or recycling, as before. The selected group's No decision must not be read as rolling back a separately approved completed group. Scoped recovery may remain committed if the following expected-state check fails. The current whole-selection active/dependency admission remains; exact reference active-state/queue filtering is not established here. Dialog wrapping, DPI, cancellation, preference failures, recycle outcomes, state changes and installed IDM/UDM comparisons remain runtime-unverified.

All five production native targets built successfully with exit code 0 and report 1.45.0. The captured source hashes remained unchanged; executable sizes and SHA-256 hashes are recorded. Compilation and artifact identity do not establish removal behavior at runtime.

Both IDM specimens were freshly hash-checked against the retained export's reference digest. No reference application, UDM UI, removal operation or acceptance test was executed during this increment. Tests, installers, installation and publication remain deferred; full parity remains unfinished.
