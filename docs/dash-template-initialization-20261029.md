# Live DASH template initialization locators

UDM now accepts an inherited Initialization child under SegmentTemplate for live capture. The nearest child is retained through MPD/Period/adaptation/representation inheritance. If the initialization template attribute is present, it takes precedence; otherwise sourceURL is a literal URI reference, including literal dollar characters. An omitted sourceURL resolves against the selected BaseURL. A locator resolving to the manifest itself is rejected.

The optional inclusive range is checked for integer precision, ordering and a 256 MiB maximum. Ranged initialization uses strong source-version discovery and existing conditional range transfer, protected receipt, recovery and assembly bindings. Ordinary template media segments retain their existing transfer path. Child initialization without a range uses the existing whole-resource receipt path. Duplicate initialization children and template RepresentationIndex remain rejected.

Extension 0.63.67 recognizes these live selections, collects initialization-origin credentials using the existing scoped request policy, and checks live-dash-template-initialization on the final selected tracks before handoff. The native host advertises this capability. Chromium and Firefox are mirrored; four script syntax checks passed and six staged extension files were hash-verified.

This implementation was written in UDM's existing planner/resource-store structure. The precedence and literal-locator behavior were checked against the AndroidX Media reference implementation, specifically SegmentTemplate.getInitialization and its documented initializationTemplate precedence: https://raw.githubusercontent.com/androidx/media/release/libraries/exoplayer_dash/src/main/java/androidx/media3/exoplayer/dash/manifest/SegmentBase.java . No reference source was copied. This is compatibility evidence, not an observation of IDM runtime behavior.

All five native production targets and the installer compiled successfully; compiler warnings remain. The unsigned candidate and source hashes are recorded in the [build record](validation/dash-template-initialization-build-20261029.json). Runtime network, browser, inheritance, range, restart and playback tests remain deferred at user request. The recorded single-Period and multi-Period browser parser also resolves inherited child initialization into its existing whole/ranged segment contract, with template-attribute precedence and literal sourceURL handling. This uses the existing recorded transfer interface and does not require a new native capability. No installation or publication is performed.
