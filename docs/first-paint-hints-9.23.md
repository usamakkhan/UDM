# Prepared details on first paint - UDM 9.23

UDM 9.23 / source extension manifests 0.72.87 displays the matching immutable prepared snapshot while File Info's existing owned reader waits for Manager. Previously, an already-admitted browser download with a prepared snapshot still painted a blank loading form. The snapshot was considered only after revalidation. The loading form now shows its address, destination, category, description and size provenance immediately without reading live metadata, resolving credentials, inspecting files or taking Manager.

These are advisory values. Track totals are labelled Selected track size, estimates keep their approximation marker, browser-reported sizes remain reported and stored direct sizes are labelled Recorded size. They never claim Exact final size. Unknown and absent sizes remain unknown, not zero. Unsafe server names and replacement/unvalidated-address fallback names are suppressed. A snapshot for another job supplies none of its values.

Start, Download Later, Schedule, destination/category editing and Use server name remain disabled while current membership, request and metadata are checked. Cancel retains the existing owned cleanup. Only the reader's coherent current result constructs the editable form. The worker replaces obsolete metadata before enabling actions. No immutable snapshot authorizes a transfer, destination reservation or overwrite. Pending unbound media admission keeps its existing binding path. Calls with no prepared snapshot retain the fast unknown loading shell until their worker supplies details.
