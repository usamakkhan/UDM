The HTTP/1 inspection path now recognizes application/vnd.apple.mpegurl, application/x-mpegurl and application/dash+xml, including case and MIME parameters. Both ordinary responses and multipart-range parts share the predicate. [Complete before/after evidence and helper hash](validation/network-playlist-recognition-20261008.json).

HTTPS stays encrypted. No driver, certificate, installed helper or browser setting was changed.

## Network handoff failure handling — 8 October 2026

A decision callback exception previously escaped the HTTP parser and ended the gateway connection. Failed decisions now leave the original response flowing, record one DecisionFailures event and disable further callbacks on that connection. Other connections have independent parser state. Candidate observations now expose canIntercept: only the first full GET/200 response without a Range request is eligible. HEAD, range and multipart observations and later pipelined responses cannot claim stream ownership. CLI gateway statistics include the decision-failure count.

The saved baseline passed 53 and failed four new regressions. With the fix and six eligibility regressions, all 63 core checks pass. A real loopback relay verifies the exact original request and response bytes survive an exception from the offer receiver. The helper builds with /W4 /WX. [Before/after evidence and binary hash](validation/network-handoff-failure-20261008.json).

The exception simulates a failed receiver; no actual broker-process crash, driver-enabled gateway or public browser session was exercised. The desktop candidate/decision protocol and durable download ownership transaction remain unimplemented. The candidate is not installed. Newly generated compiler objects were removed after qualification; binaries, source and reports remain.

## Gateway capture observations — 8 October 2026

The explicit TCP gateway now retains recognized HTTP candidates instead of only counting them. Each record includes a helper-local observation ID, unique connection ID, PID and process creation time, plus request and response metadata. Bounded retention keeps at most 64 records and 48 KiB of field bytes, with visible eviction/rejection counters. Multipart ranges retain their shared connection identity and distinct range metadata. The explicit CLI gateway result serializes these observations, preserving non-UTF-8 field octets as binary JSON rather than changing them or failing serialization.

Final core acceptance: 73 passed. An earlier live signed-driver build passed 79 with one failed IPv4 opaque fixture because Windows rejected its loopback bind (10013); the cause remains unestablished. Its successful IPv4/IPv6 HTTP forwarding and interception fixtures validated candidate/process attribution; excluded and opaque traffic did not create candidate records. The final live rerun was canceled at Windows elevation before launch, so it is not a final-binary live pass. [Reports and final helper hash](validation/network-capture-observations-20261008.json).

These observations do not hold response bodies or replay credentials and cannot themselves acknowledge download ownership. Observation IDs can repeat in a new helper instance. The desktop broker still exposes only Watch/Snapshot/Stop. Its future offer protocol must bind helper-session and connection identity, preserve a replayable request durably, acknowledge cancellation before committing the catalog transaction, and retain an explicit recovery path for unknown outcomes. The existing browser prepare/commit workflow cannot simply be called before network cancellation. No personal app, driver runtime, browser extension or installer was replaced; temporary compiler objects were removed.

## Authenticated desktop capture interface — 8 October 2026

The broker now accepts an explicit Capture command with validated destination ports for its existing process scope. Watch remains metadata-only by default. Capture snapshots bind observations to the authenticated pipe session nonce and a gateway generation; changing process roots stops capture. Repeated identical capture requests keep the gateway; port changes destroy the old gateway before replacement, and failed creation leaves capture off. The native Monitor API validates ports before IPC and checks returned capture-session identity and bounded record shape.

The native diagnostic CLI exposes this through `Udm.Monitor.exe --capture PID[,PID...] PORT[,PORT...] [seconds]`. It stops tracking exited roots by checking their held process identity and signaled exit state. No GUI toggle, retained response body, replay credential handoff, cancellation acknowledgement or durable download ownership was added. Automatic takeover stays false.

Validation: 37 native broker/protocol checks and 73 network core checks pass. The command traverses a real framed named pipe; production session lifecycle is tested with a fake gateway factory, including unscoped admission, unchanged ports, replacement, failed startup, null startup and repeated stop. The native monitor and helper rebuilt; backend objects other than Network were reused. The current helper's elevated end-to-end capture mode has not run: the earlier canceled Windows elevation was not retried. [Evidence and hashes](validation/desktop-capture-broker-20261008.json).
