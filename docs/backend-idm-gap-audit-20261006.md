# Backend gap audit, 6 October 2026

The validator correction in `Transfer.cpp` closes one ranged-response integrity defect; it does not establish IDM backend parity. This audit distinguishes code-visible limitations from comparison cases still lacking reference acceptance. The 29 September research status is historical and must be checked against current source before treating an item as missing.

| Priority | Area | Current UDM evidence | Next acceptance target |
| --- | --- | --- | --- |
| High | Browser request handoff | The local candidate supports captured POST bodies up to 4 MiB. [Crash-recovery checks](post-crash-recovery-20261008.md) cover an exact-boundary lost prepare reply and simulated worker restart, two concurrent exact-boundary requests across native catalog reload, and safe release after an isolated Edge process restart when its response does not survive. Browser APIs may expose fewer bytes; arbitrary already-issued single-use responses still cannot be adopted. | Qualify successful live browser/native crash and restart, including Firefox, with exact request bytes, session, output, and one-use semantics. |
| High | Live media | The newer [live subtitle candidate](validation/live-subtitles-20261008.json) records selected self-contained clear WebVTT captions, maps timestamp resets, restores saved segments, and embeds them in MP4. Native recovery and real isolated Edge panel acceptance pass. A [focused real Firefox panel test](validation/live-subtitles-release-20261008.json) also passes. The newer [mapped-header candidate](live-subtitle-map-20261008.md) also supports separate live WebVTT initialization headers and passes focused native, Edge and Firefox acceptance; it is not packaged or installed. Public-site coverage and all-empty caption tracks remain open; historical broader Firefox timeout causes remain unestablished. This candidate is packaged but not installed. The [SABR side-track correction](sabr-unselected-compression-20261008.md) skips unrelated compressed segments. The newer [staged gzip/Brotli candidate](validation/brotli-release-20261008.json) also decodes selected compressed segments with bounded output; it is not installed, and public-site compression acceptance remains unverified. Encrypted media remains unsupported. Static and recorded media paths already exist. | Qualify supported formats against the installed IDM reference, then verify decoded output, pause/resume, and expiry recovery. |
| High | Automatic network-monitor handoff | `native/Network.cpp` exposes Watch and Snapshot; it does not provide an accepted observation-to-classification-to-offer-to-download ownership workflow. | End-to-end browser-independent capture, cancel/crash recovery, and coexistence tests. |
| Medium | FTP through automatic proxy settings | The local candidate honors Windows static-proxy bypass rules with semicolon or whitespace separators, routes a Windows-configured PAC URL through the existing FTP PAC resolver, and maps an explicit `ftp=http://host:port` static entry to HTTP CONNECT. A 7 October follow-up resolves Windows WPAD asynchronously and supports cancellation. Explicit PAC scripts already resolve supported direct/SOCKS/HTTP CONNECT routes. WPAD has no live network acceptance yet; other static FTP gateway routes and active FTP through a proxy remain unsupported. | Route, DNS, authentication, failover, and data-channel tests using controlled proxies. |
| Medium | Grabber/offline sites | Current grabber does not establish JavaScript-rendered exploration, browser-cache reuse, or automatic session sharing across independent projects. | Authenticated rendered pages, offline navigation, cookie changes, and restart/resume fixtures. |
| Qualification | Transport and resilience | HTTP/2 negotiation, dynamic range splitting, checkpointing, retries, and resume validators exist. Public-site speed equivalence, QUIC behavior, broader proxy variants, physical power loss, and sleep recovery remain unqualified. | Controlled measurements and interruption tests. Do not call these missing solely from absent acceptance. |

The installed IDM reference and research builds differ; a UDM limitation is not automatically a proven IDM advantage. These rows are implementation and validation priorities, not a parity percentage. The validator regression passed in an isolated native build: 2,549 checks, zero failures. No installation or browser activation occurred in this audit.
