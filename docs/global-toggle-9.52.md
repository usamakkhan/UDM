# Speed Limiter On/Off ownership — 9.52 / extension 0.73.16

Move Speed Limiter On/Off persistence off the UI thread. Preserve the live remembered rate, startup choice and limiter mode, update radio state only after a committed result, and keep local selection/sort/paint responsive. Reserve Close and explicit Exit until the accepted save is acknowledged; cancel an ordinary close through Show even after acknowledgement, and cancel deferred Exit on save failure for explicit retry. Controlled held-model command return improves from 2,612.99 ms on frozen 9.51 to 9.49 ms. Build five native 9.52 products; pass 154 backend and 864 native UI assertions on child-attested desktops. Source browser manifests advance to 0.73.16. Installed 8.68 remains unchanged; installed IDM parity and the earlier total-time gate remain open.

## Command and persistence architecture

On/Off submits an immutable enable/disable choice to the existing owned settings worker. Acceptance reserves the shared decision guard before waiting for the model. The worker derives the rate from the latest live settings, preserves startup and aggregate/per-download mode, and persists through the canonical durable transaction. On remembers the last active/remembered rate; repeated Off never replaces that rate with zero. No optimistic disk write or radio state is announced.

Keep the main window enabled for painting, resizing, Select All and sorting while acceptance is pending. Freeze conflicting menu and toolbar actions. A result is consumed on the identity-checked maintenance notification or timer fallback; the thread is joined and its guard released before acknowledgement. Restore the prior toolbar advice and update the existing native limiter radio from the owned result without a new Manager read. Normal later refresh revalidates toolbar advice against current selection.

Close waits for the accepted save. A normal close remains cancellable by Show or another command, including between save acknowledgement and replay. An explicit Exit remains reserved through Show and duplicate commands. Replay is an owned state decision, not an unconditionally queued WM_CLOSE. Notification failure leaves timer retry available. Timer and notification handlers return directly after replay, because it may destroy the window. Save failure keeps the prior catalog, cancels deferred Exit and leaves the app open for explicit retry. Forced destruction joins the accepted worker before releasing its owner.
