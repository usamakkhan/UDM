# Find input bounds and empty submissions — UDM 1.52.0

The current reference and installed IDM binaries again match SHA-256 03CC62E9ADB77A380F9DC12F67CCAAEE5106F12844AA73CE32C914DDD16D607C. Retained instructions at 0x004b1583–0x004b1596 pass 0x800 as GetWindowTextW capacity for the Find dialog. The zero-result branch at 0x004b159c–0x004b1612 skips copying both stored query strings but continues to read the field/case/whole-string options. The dialog can therefore accept an empty input while retaining its prior query. The inline handler separately uses the same capacity at 0x00483fc5–0x00483fd0 and clears session strings on empty input at 0x0048403a–0x00484051, without invoking its nonempty persistence helper. These are static Unicode-path observations, not runtime or fresh REA evidence.

Both UDM submission paths now read through GetWindowTextW into a 2,048-unit buffer, accepting at most 2,047 UTF-16 units plus the terminator. They do not set an edit-control input limit: the inline draft can remain longer, while the committed query is the bounded prefix, following the observed reference sequence. Find-dialog acceptance replaces the prior text only for a nonempty read and applies the current options in either case. An initially empty query can be accepted without the previous Enter text to find error. The all-fields-unchecked recovery still requires a field before acceptance. Inline empty submission retains its distinct session-clear and no-saved-text-overwrite rule.

A UTF-16 buffer limit can split a surrogate pair. Simply converting the prefix with UDM's strict UTF-8 helper would reject that input; dropping the last unit or replacing it in the matcher would change the reference's Windows string needle. Find text now has an exceptional canonical representation: Text remains valid UTF-8 with U+FFFD for each unpaired unit, while optional TextUtf16 holds the exact raw sequence as integer units. This field is emitted only when the sequence contains an unpaired surrogate and is limited to 2,047 units. Valid ordinary Unicode queries retain their existing shape with no extra field.

Normalization checks the array type, bounded length, integer unit values from 0 through 65535, required unpaired-unit condition and consistency with the printable UTF-8 Text. Existing single-line/NUL rejection remains. Malformed saved input normalizes to an empty query through the existing recovery policy; explicit setters reject noncanonical queries through their equality validation. The array stores only user-entered query text, never captured download metadata or decrypted addresses. It is part of the saved query and is not a separate browser/IPC setting.

Find and inline controls restore the raw sequence through SetWindowTextW. DownloadSearch folds and compares that sequence as Windows wchar_t units, retaining the existing case/substring/whole-string logic. Cursor and filter cache identities include the metadata, so a literal U+FFFD query is distinct from an unpaired surrogate with the same printable fallback. Inactive filters erase both text and raw-unit metadata from their effective matcher; a retained query cannot accidentally remain active. Captured source strings continue through their existing strict UTF-8 path.

Explicit saves still happen before committing the accepted query to the UI. A failed save leaves the old committed state and the open dialog/draft available for retry. This implementation does not reproduce reference registry storage or its legacy ANSI-control fallback. Older UDM normalizers do not understand the optional raw-unit metadata and can reduce an exceptional query to its printable fallback; no lossless downgrade guarantee is made. Historical valid queries longer than the new submission bound are not destructively rewritten merely by loading settings; a subsequent UI submission applies the bound.

The reference dialog copies nonempty text and checkbox state before its all-fields-unchecked rejection. UDM still commits only a valid accepted query. Cancelling after that rejected attempt can therefore retain different parent/session state; this invalid-attempt side effect remains a source-level parity gap, separate from the empty/length behavior implemented here.
