# Background periodic history checkpoints — UDM 1.48.0

Source inspection found that the main window's timer called Manager::tick, which compared the catalog and synchronously called save every third tick when dirty. Earlier changes released the manager lock for serialization and file IO, but the timer's own thread still performed that work. This finding concerns UDM's call chain; it does not establish IDM's private checkpoint implementation.

The timer now requests work from one lazy, owned PeriodicCheckpoint worker. A boolean pending request bounds the queue: requests during a save coalesce into at most one subsequent check. The worker performs the dirty comparison under the manager lock and calls save without an outer manager lock. Idle checks retain the existing no-rewrite behavior. Explicit user-action and transaction saves remain synchronous.

The existing sequence and write-mutex rules remain authoritative. Older snapshots cannot replace newer published snapshots, errors are reported through storageError using the existing sequence guard, and completionSaved still requires the matching successfully published catalog state. The asynchronous wrapper does not report an unsuccessful save as durable. Failed writes are retried at a later periodic request. A failure to create the worker is surfaced through the timer's existing error path and storageError.

Requests are issued while holding the manager lock, so shutdown's stopping flag prevents a late timer request from restarting work after the join. Shutdown cancels pending checks, joins any running checkpoint outside that lock, waits for transfer/relocation work, and performs its final synchronous save. The worker can restart if the final save fails and the app resumes. Its member is declared last so destruction joins it before callback-visible manager state is destroyed, including exceptional shutdown. It never detaches or captures a window handle.

Snapshot creation and dirty comparisons still take the manager lock; explicit saves may wait for an in-progress write, and scheduler transitions can still save on the timer thread. Slow storage can still delay shutdown. This change does not establish a measured speedup or eliminate all UI waits. Existing idle-checkpoint assertions were adjusted to await eventual background persistence and synchronize their direct state changes; they have not been run.

All five production native targets built successfully with exit code 0 and report 1.48.0. Captured source hashes remained unchanged; executable sizes and SHA-256 hashes are recorded in the build receipt. Compilation does not establish runtime behavior. Browser source remains 0.63.85. Runtime tests, installer creation, installation and publication remain deferred. Full IDM parity is unfinished.
