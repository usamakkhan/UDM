# Responsive generic queue selection — UDM 9.32

UDM 9.32 / source extension manifests 0.72.96 closes the synchronous queue-selector preparation gap left in 9.30. The generic selector previously called queueNames and queueDisplayLabels separately before constructing its window. A busy catalog delayed the window and a concurrent edit could make those two reads describe different queue cohorts.

The generic path now constructs its real controls immediately and starts an owned QueueChoiceTask. The reader acquires Manager cooperatively, defers another accepted File Info command, and reads stored queue identities and collision-resolved labels under one lock. It publishes an immutable result before sending a weak window notification. It changes no download, settings, catalog or accepted-command guard. Cancellation wakes acquisition and teardown joins the owned worker. Notification failure cannot retract the result.

While loading, the queue combo, create action, processing/remember options, OK and optional Schedule are disabled. Enter and programmatic acceptance cannot submit partial choices. Cancel and the window close remain available. Failure stays inside the selector and exposes Retry; retry consumes the old result before starting a fresh read. After preparation, the controls use only their local cohort, including new names entered through Create queue. A returned create flag is advisory; the caller's existing canonical command owns final validation and persistence. Schedule retains the actual selector as its parent.

File Info continues supplying the cohort it already prepared in 9.30. That path starts no second queue reader and retains immediate selection even while Manager is locked. Both paths now expose an explicit Cancel button. Shared QueueChoiceView lives in the independent task header; FileInfoActionTask retains its existing Start/Later semantics.
