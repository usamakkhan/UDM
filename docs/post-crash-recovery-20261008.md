# Captured POST crash-recovery candidate

The browser transaction suite now exercises an exact 4 MiB captured POST when the `capture-prepare` reply is lost. It simulates a browser worker restart, recovers the native transaction, and verifies that the body stays out of the browser journal while the prepared bytes survive and one commit creates the download. The Chromium and Firefox transaction cases passed: 83 checks total.

The native prepared-request aggregate budget is now 16 MiB. Its prior 8 MiB budget could hold only one protected 4 MiB POST, despite the 4 MiB per-body limit and 32 MiB catalog limit. The native suite now prepares two distinct exact-boundary POSTs concurrently, reloads the catalog, verifies both normalized requests byte-for-byte, and commits each once. The isolated native build passed 2,568 checks with zero failures.

The complete desktop and native host were then built in the same isolated candidate. A fresh Edge profile passed all 12 live POST fixture checks, including one exact 4 MiB form, the above-boundary browser fallback, encrypted native storage, one native POST, byte-identical output, selected-file forms, and persistent native messaging. The fixture's temporary native-host registration was removed on exit. The first fixture invocation stopped before launching Edge because local `playwright` was unavailable; the passing run used the workspace's bundled Playwright package.

An opt-in Edge process-restart case in `tests/post.native-live.cjs` now holds the reply after native `capture-prepare` for an exact 4 MiB POST, closes the isolated browser profile, reopens the same profile, and reloads the unpacked extension. The fresh run passed all 13 fixture checks. Edge did not preserve that original response as a resumable download; UDM released the prepared capture, cleared the journal, and made no native POST or job for it. This verifies the safe release path across a real browser restart, not successful transfer recovery. Earlier attempts using Edge's unavailable ServiceWorker CDP domain and `Target.closeTarget` did not establish a worker restart and are excluded from acceptance.

This is a source and isolated-binary candidate; it has not been installed or released. The 4 MiB per-body limit and 32 MiB catalog limit still apply. The live Edge case closes the browser gracefully after preparation; it does not kill the native host, simulate power loss, or prove successful adoption when the browser response survives. Live Firefox acceptance and adoption of arbitrary already-issued single-use responses remain open.
