# Publication recovery coverage — 1.2.11 and 1.2.12

Version 1.2.11 extends the live-HLS recovery protection to direct downloads, recorded media, live DASH and offline archives. A shared PublicationRecovery.hpp predicate treats present or unreadable publication/replacement journals as pending recovery. Transfer entry checks prevent retries from modifying old working files, including a direct-download data file hard-linked to journal-dependent staging. Additional assembly checks prevent output truncation before publication. Direct-download RAII cleanup now retains staging while recovery is pending, and recorded-media catches use the nonthrowing filesystem-status check instead of replacing the original exception.

Source tracing then found a separate regression introduced by the uninstalled 1.2.9 candidate: publishFile required the job to belong to Manager::jobs, but setStreams deliberately creates private audio/video child jobs outside that catalog. Their transfer calls still publish their individual track files. Version 1.2.12 snapshots membership and checks it remains unchanged, permitting these internal children while continuing to reject membership changes, destination changes and modified replacement metadata during verification. Installed 1.2.8 does not contain that regression.

The final native build target is 1.2.12 and includes both increments; 1.2.11 is not being built or packaged separately. Browser 0.63.82 is unchanged. All five production targets compiled successfully as 1.2.12. Source and binary hashes are recorded in [build evidence](validation/publication-recovery-coverage-build-20261030.json). Tests and installer creation remain deferred, and no installation or publication is planned for this development increment.

This work preserves data needed by the existing recovery flow; it does not establish full recovery acceptance. In particular, private media-child journal recovery across restart and broader concurrency/rollback scenarios still need qualification. The full IDM parity objective remains unproven.
