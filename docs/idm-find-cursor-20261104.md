# Find Next session cursor, UDM 1.36.0

The retained IDM routine 0x0047c2a0 reads a stored next-row index from main-window offset 0x1820. It scans forward from that index, selects a matching row and stores the following index. After reaching the end from a nonzero cursor it resets to zero and scans the list again. An unsuccessful pass starting at zero shows the not-found result. This differs from UDM's previous behavior of deriving the start from the current selected row on every invocation.

Instruction inspection confirms the cursor read at 0x0047c303, zero comparison/reset at 0x0047c377/0x0047c384 and successful next-row store at 0x0047c422. Construction initializes it at 0x0046279d. The category callback at 0x00478370 resets it at 0x00478721. The rebuild/selection-restoration path at 0x0046ba60 stores the row after its restored first selection at 0x0046bbb8; if no selection is restored, that path does not overwrite the cursor. The changed-search rebuild helper at 0x00483e50 resets it at 0x00483ef7. This is retained Ghidra/instruction evidence, not a new REA session or runtime observation. Reference and installed executables were hashed again and both match 03CC62E9ADB77A380F9DC12F67CCAAEE5106F12844AA73CE32C914DDD16D607C (6.43.10.2).

DownloadFindCursor now owns the session's next-row index. Ordinary selection/focus changes in an unchanged view do not replace it. Find Next prepares the current query, scans from that index, then performs a full pass from zero when necessary. A match advances the cursor to the following row. An unsuccessful full pass leaves zero. The full wrapped pass can revisit the earlier tail; it is intentionally not shortened to a single modulo traversal, matching the reference control flow. Matching still uses per-row owned metadata outside the manager lock.

Changing the normalized query text or options restarts at zero. A changed effective category/queue/project/text-filter scope also resets to zero. After a same-scope list rebuild or explicit sort change, the UI synchronizes the cursor to the row after the first restored selection when available. If there is no restored selection it retains the numeric cursor, which can subsequently wrap if beyond the new end. The query reset is applied after refresh, so it takes precedence over a simultaneous rebuild. These rules integrate the observed reference patterns with UDM's current immutable list refresh; exact equivalence of every legacy callback and automatic reorder remains unqualified.

For a found row, UDM clears prior selected/focused states, focuses the list, requests visibility with partial visibility allowed, selects/focuses the result and advances the cursor. The reference Find call requests LVM_ENSUREVISIBLE with lParam 1. This increment does not introduce pixel/DPI/scroll acceptance evidence. Cursor position is not stored with the saved query; a new main window starts at zero.

FindDialogUiTests now includes two manual-selection cases that distinguish a stored cursor from restarting after the selection. These assertions were maintained but not compiled or run. Current reference quick-search coupling, no-field modes, long-query limits, rare reentrant refresh paths, runtime metadata/rebuild behavior, keyboard/accessibility, scrolling and IDM comparison remain separate work. Tests, installer creation, installation and publication remain deferred. Full parity is incomplete.
