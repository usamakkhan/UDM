# IDM Status percentage display, UDM 1.27.0

Reference list insertion and the failure-update assembly preserve percentage text when received bytes are positive, rather than replacing it solely because the transfer has failed. With no received bytes, the failure path chooses Not Found, Error or blank from the result code. Complete is applied from the completion state separately. The formatter queries the user's Windows decimal separator, stores its computed percentage as float, truncates the whole part and fractional hundredths separately, and joins those integers with the separator. It guards percentage writes at 105 percent.

UDM's shared main-list/Scheduler status helper now gives valid retained coverage priority over failure labels for Downloading, Paused, Pausing, Queued and Failed records. Media duration and completed duration take priority, then known segment counts, then known byte size and received bytes. Status text is no longer derived from rounded permille, nor overwritten by the byte ratio when a media clock exists. The 100.0 multiplier, float conversion, separate truncations and below-105 guard follow the traced byte-display path. This can expose binary-float truncation effects near hundredth boundaries; it is not a decimal rounding implementation.

Unstarted failures still show Error or Not Found for HTTP 404. Neutral transfers with no positive known coverage now have blank status text. Unknown/invalid totals cannot supply an invented percentage; a partially received unknown-size failure has no percentage/error replacement in this helper. The reference can retain previous cell text on guard/unknown paths, whereas UDM's snapshot renderer computes the current cell from the current record, so exact stale-cell behavior is not claimed. Live recording keeps explicit unbounded state text and has no invented completion percent. UDM-specific assembly phases and quota-wait text remain explicit. Stored Failed state, error details and retry behavior are unchanged.

The display can say 100.00 percent when all bytes or coverage are present before publication. Only the actual Complete state produces the Complete label; existing progress-bar/permille publication guards remain unchanged. Failed retained-coverage display now agrees with the source of the 1.26.0 Status ordering keys, while that comparator's traced byte-ratio/media-percent distinction is retained.

The decimal separator is read with GetLocaleInfoW(LOCALE_USER_DEFAULT, LOCALE_SDECIMAL), preserving Unicode separators. The reference uses GetLocaleInfoA with the same locale/type. A comma fallback matches the reference's failure path. A per-thread string cache and atomic generation avoid an OS locale query on every row. MainWindow's settings-change handler invalidates that generation and resets row snapshot references so unchanged records repaint on the next refresh. Scheduler cells already refresh through the shared helper. No system or CRT locale is changed.

Microsoft documents the [locale retrieval buffer/count contract](https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-getlocaleinfow), [decimal separator data](https://learn.microsoft.com/en-us/windows/win32/intl/locale-sdecimal) and [locale settings-change notifications](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-settingchange). Unicode-versus-ANSI separator equivalence, x87-versus-x64 boundary arithmetic, media/live mappings and actual rendered behavior still need runtime qualification.

See [reference trace](reference/idm-status-display-20261104.json) and [build receipt](validation/idm-status-display-build-20261104.json). Existing toolbar status assertions were maintained for the changed contract, including failed retained progress and media-clock precedence, but were not compiled or executed. Runtime tests, installer creation, installation and publication remain deferred by instruction. Full IDM parity is incomplete.

All five native production targets built successfully at 1.27.0. Product versions, executable hashes and unchanged feature-source hashes were verified in the receipt. Existing test assertions were not compiled/executed, and no runtime behavior was verified in this increment.
