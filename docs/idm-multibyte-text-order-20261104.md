# IDM multibyte text ordering, UDM 1.25.0

The reference's Description and Referer callbacks route populated text through helper 0x0040d830. Assembly shows its call to 0x0063eac9 and preserves EAX through the callback returns; the retained export identifies that target as VS2008 `__mbsicmp`. Unlike the bounded UTF-16 getter used by filename/path/page comparisons, these columns use CListCtrl::GetItemText returning CStringA. That getter sends LVM_GETITEMTEXTA and grows its buffer until all text fits.

UDM now builds temporary CP_ACP comparison keys from the full Unicode Description and Referer values, once per row on a cache miss, then uses `_mbsicmp`. First-NUL termination follows C-string retrieval semantics. Empty-last ascending and reversed descending order are retained. Neither the 255-unit bound nor pre-lowercasing of UTF-8 bytes is applied to these two columns. Raw UTF-8 values remain the reuse keys so case-only edits also invalidate ordering conservatively. Referer header decryption remains cached outside the manager lock. Full stored and displayed Unicode values remain unchanged; characters unavailable in the ANSI code page can compare equal after Windows replacement/best-fit conversion.

Microsoft documents [multibyte comparison and its error sentinel](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/stricmp-wcsicmp-mbsicmp-stricmp-l-wcsicmp-l-mbsicmp-l?view=msvc-170), [the startup ANSI multibyte code page](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/setmbcp?view=msvc-170), and [CP_ACP conversion](https://learn.microsoft.com/en-us/windows/win32/api/stringapiset/nf-stringapiset-widechartomultibyte). These APIs depend on runtime locale/code-page state. System ACP conversion mirrors the reference's ANSI list retrieval path; the exact active reference CRT locale/code page and cross-version equivalence have not been verified at runtime.

UDM additionally guards CRT comparison errors. A comparator error aborts that stable-sort attempt, restores original catalog order and repeats the entire sort using case-insensitive byte comparison. This keeps one comparison relation for the whole attempt and prevents an error sentinel from being interpreted as an ordering result. This fallback is a UDM correctness guard, not a claim about IDM's error behavior. No process-wide locale or code page is changed.

See [reference trace](reference/idm-multibyte-text-order-20261104.json) and [build receipt](validation/idm-multibyte-text-order-build-20261104.json). Runtime tests, installers, installation and publication are deferred by instruction. Full IDM parity remains unproven.

All five production executables built successfully at 1.25.0. Product versions, artifact hashes and unchanged feature-source hashes were verified and recorded. This establishes compilation and artifact identity only; no runtime tests were performed.
