# Cached Time Left estimates — UDM 1.44.0

The retained IDM Time Left comparator at 0x004b7b30 begins with the record's cached integer rate at +0x538. Assembly at 0x004b7ba3 loads it; 0x004b7bb9 checks the optional session pointer, and 0x004b7bc2 through 0x004b7bd5 replace that value only when session +0x24 is nonzero. Ordinary remaining bytes are then divided by that selected rate. The inspected list-insertion path at 0x004cd38a independently tests cached rate +0x538 against 10 before dividing remaining bytes and formatting the cell. This supports retained estimates without requiring a live rate object.

The historical [GUI table](gui-parity-2026-10-18.md) described Time Left as blank when idle. That blanket statement is too broad for this cached-rate path. Its retained idm-main-columns-wide.png frame also contains nonzero Time Left text alongside blank Transfer Rate cells, but a still image alone does not prove those records' active/paused states. No new reference execution was performed. Both the retained reference executable and installed IDM specimen were freshly hashed and still match the SHA-256 recorded in the source record.

UDM previously derived list ETA only from current Job::speed and required Downloading state. Manager::tick now stores each current Downloading attempt's measured integer rate as LastTransferRate, including a genuine zero rate sample. Inactive ticks preserve it while the live meter resets normally. The regular job snapshot/checkpoint path already compares and saves all record fields, so this value participates in ordinary periodic and explicit history saves. It is also included in the immutable list projection, ensuring cached-rate edits invalidate affected row views/sort keys. New catalog/redownload records use existing metadata whitelists and do not inherit this cache; older records without a cache keep unknown estimates until sampled.

Main-list and Scheduler Time Left choose a positive live integer rate for Downloading records, otherwise the bounded cached integer rate. The Time Left comparator uses the same selection without imposing the cell's display threshold. Paused, Failed and Queued records may use the retained estimate; Complete, live recording and merging/assembly states remain excluded. Unknown sizes, invalid received/coverage/baseline/elapsed values and missing/nonpositive rates remain unknown, with the existing numeric saturation and 10,000-hour formatting boundary. List cells still require a rate above 10 B/s. Transfer Rate cells and progress dialogs continue using their existing measured/active paths; the cache does not create new traffic or make a paused estimate count down with wall time.

Finite adaptive media retain the existing verified-coverage/current-attempt-elapsed calculation when its saved clock is valid. The two-argument downloadSecondsLeft API still requires active Downloading state; only the list-specific path enables stopped states. Cached estimates represent transfer work remaining at the sampled rate, not scheduler waiting time, reconnection latency or a completion guarantee. A zero sample replaces the cache during active measurement; stopping afterward preserves zero rather than inventing a last-positive rate.

UDM's explicit record persistence and status mapping are implementation choices pending runtime comparison.
