# UDM 5.45 and IDM 6.43 build 10 parity audit

November 8, 2026. This audit extends the [P0–P6 architecture plan](idm-parity-architecture-plan.md) and [November 7 execution plan and granular inventory](idm-parity-execution-plan-20261107.md). Scope includes browser capture, transfer, desktop, storage, scheduling, Grabber, Windows integration and release. UDM retains its own name, artwork and implementation.

The first implementation pass follows the completion bounds, File Info timing and extra range requests from this audit. [Implementation and validation](validation/completion-file-info-range-followup.md)

Its existing silent command-line route accepted an owned localhost download. One launch-to-verified-file observation was 2.515 seconds. The interactive comparison requires an authorized reference.
- The live IDM completion dialog exposed Open, Open with…, Open folder, Close and a persistent suppression checkbox. It displayed both 1.00 MB and 1048576 Bytes. It exposed the address and destination as edit controls. Minimize and Close were enabled and Maximize was disabled. Windows returned “failed to activate captured window” on a fresh retry, so button actions and default focus remain open. The current screenshot did not render the dialog reliably.

- The vendor documents takeover by file type, force/bypass keys, category destinations, Start and Later, the in-player format menu, and background media transfer. It documents normal versus synchronization queues, retry-to-tail behavior, and stop times independent of start. Use these as workflow requirements. ### Current paired transfer results

Each app ran twice per case with alternating order and deterministic owned HTTP/1.1 inputs. All 16 outputs matched the expected length and SHA-256. UDM was isolated with eight connections configured. IDM used the existing profile, and its configured limit was not changed or verified. Packaging ran concurrently. Wall time includes process dispatch through verified output, including polling and file hashing. These are diagnostic measurements.

| Origin | UDM seconds | IDM seconds | UDM HTTP requests | IDM HTTP requests | UDM / IDM refusals |
| --- | ---: | ---: | ---: | ---: | --- |
| Healthy ranged, 24 MiB | 3.055 / 2.270 | 2.942 / 2.282 | 13 / 13 | 7 / 7 | 0 / 0 in both trials |
| Two allowed connections, 24 MiB | 4.648 / 7.596 | 5.552 / 6.559 | 6 / 6 | 3 / 3 | 6 / 9, then 6 / 10 |
| Range ignored, 16 MiB | 3.813 / 3.900 | 3.398 / 3.506 | 2 / 2 | 4 / 4 | 0 / 0 in both trials |
| Forced close after 3 MiB, 24 MiB | 2.595 / 2.602 | 2.377 / 4.134 | 18 / 18 | 14 / 18 | 0 / 0 in both trials |

UDM used nine and ten dynamic splits in the healthy ranged runs. Higher request count was reproducible, while wall times were close and excess bytes changed direction between repeats. Measure split-trigger decisions, cancellation, and tail goodput before changing allocation. On the two-slot case UDM had fewer refusals in both runs, with opposite timing results. UDM consistently made fewer requests on the no-range input and was about 0.4 seconds slower across the two trials. Trace process dispatch, probe and file publication before assigning that difference to sequential I/O. Under forced drops UDM's excess bytes were lower in these two trials. ## Architecture boundaries and invariants

| Boundary and owner | Contract | Failure handling |
| --- | --- | --- |
| Player observation in browser capture.js, streaming-capture.js and site adapters | Bind an observation to browser session, tab, frame, document, video visit, player and request time. Bound observer work and preserve original playback flow. | Reject ads, protected media, wrong video, older visits and incomplete evidence. Browser-observer fallback must belong to the same visit. |
| Catalog and panel in content.js, formats.js, background.js and popup | Publish coherent ready choices with stable representation, audio, captions, container, source kind and revision. Announce readiness or a concrete failure accessibly. | Cancel stale work and preserve focus by stable choice key. A disappearing format yields an explicit refresh or alternative. |
| Browser/native bridge in native-bridge.js, media-receipts.js, Bridge.cpp and capture transactions | One selection owns one admission receipt, one prefetch lease and at most one durable job. Dispatch and File Info first paint are independent of optional discovery. | Reconcile retries with the original receipt. Never silently replay a submitted non-idempotent browser request. |
| File Info and prefetch in CaptureAdmission.cpp, CapturePresentation.hpp and App.cpp | File Info can foreground independently. Start adopts the staged bytes, Later transfers ownership to the selected queue, and Cancel releases it. | Accept asynchronous details only for the live offer and output revision. A late response cannot change a user-selected destination or bring the main list forward. |
| Transfer in Transfer.cpp, Streaming.cpp, Adaptive.cpp, DashManifest.cpp and Ftp.cpp | Validate entity and intervals before counting unique bytes. Record real rate separately from retained bytes, retransmission and finishing. | Recover from verified checkpoints. Renew stale sessions through an explicit same-job transition, preserving selected tracks and verified coverage. |
| Size and publication in MediaSize.hpp, FileWorkflows.cpp and Core.cpp | Distinguish resource length, track bytes, and exact output. Reserve destination, validate staging, publish atomically where possible, and commit completion once. | Keep the previous destination and staging recoverable on failed publication. Show exact final bytes only after proof. |
| Desktop, queues and catalog in App.cpp, Core.cpp, Queue.cpp, QueueWake.cpp and UI headers | Shared action enablement, versioned persistence, and separate queue membership, eligibility, pause state and retry deadline. | Preserve saved layout and category rules. Restart, DST and retry cannot create a second completion action or resume a user-paused job. |
| Grabber in Grabber.cpp, GrabberLinks.cpp, GrabberRendered.hpp and browser snapshot | One project owns crawl scope, result state and output map. Static and rendered content have distinct provenance. | Resume without duplicate resources. Rewrite links only for known archived entries and report unresolved dependencies. |
| Windows integration in Launch.hpp, AutomationMain.cpp, native host and installer | Own the app, manifests, registrations and data-root mapping. Verify running and installed identities separately. | Failed upgrade or repair preserves the catalog and unrelated entries. Browser activation is a separate gate. |

## Execution plan

### A. Establish a repeatable comparison

1. Freeze candidate executable and browser hashes, package digest, runtime versions and installed registry ownership. Snapshot the pre-upgrade catalog and compare IDs, queue membership, status and retained bytes after upgrade. Separate source, package, installed binaries, running executable, manifest bytes and active browser version in the receipt.
2. Pair both apps on the same machine and owned origin. Use one interceptor per disposable browser profile. Match destination volume, DNS/proxy, connection cap, limiter, browser zoom, Windows DPI and theme. Run a known 1 MiB control first. Record profile differences instead of interpreting a warmer process as a faster backend.
3. Extend the existing browser and native traces with one correlation marker and monotonic times. Record first eligible player evidence, usable panel, selection, host admission, first actionable File Info, foreground owner, first body byte, exact size proved, Start, last unique byte, verify, scan, rename and visible completion. Bound the trace and omit cookies, tokens, signed URLs, names and user paths.
4. Alternate control/candidate order and collect ten cold and ten warm repetitions for high-impact timing claims. Report median, p95, error count and sample size. Keep one-off measurements separate. Confirm the trace itself does not materially affect startup.

### B. Browser readiness, panel and handoff

1. **Readiness.** Compare natural end of pre-roll, Skip and an ad-free start. Ready means the main-player target is known and a matching row can be selected. Warm catalogs for the visible eligible player under a request budget. Test two players, an element reused across feed items, a quoted X video, Shorts, embeds, fullscreen and theater mode. No stale or ad result may replace the main-video choice.
2. **Panel details.** Measure trigger anchor and offset, caption baseline, corner radius, horizontal padding, icon alignment, row heights, separators, menu width, opening direction, long-label wrapping, scrollbar and clipping. Record hover, pressed, disabled and focus rings on dark and light content. Verify dragging, dismissing, page scroll, reload, zoom from 80% to 175%, small iframe and monitor changes. Compare where offsets persist. Retain original UDM iconography.
3. **Menu behavior.** Compare one and multiple choices, order of quality/container/audio labels, equivalent rows with distinct track identities, disabled reasons and size/units. Exercise Tab, Shift+Tab, arrows, Home/End, Enter, Escape and outside click. Preserve focus when the catalog refreshes. A ready format should be selectable on the first open. Keep tools, diagnostics and reconnect messages separate from the normal in-page path.
4. **Handoff.** Trace browser click, host cold start, active host, sleeping worker, worker restart, lost acknowledgement and two rapid clicks. Separate catalog delay, native process dispatch and File Info construction. Preserve one job when an acknowledgement is lost. Test browser takeover for ordinary files, redirects, attachment/viewer, ignored types, configured bypass/force keys, POST, blob and expiring responses. Verify enabled state and grouping of browser context menus for link, selection, page and video.
5. **Browser coverage.** Run Chrome, Edge and Firefox individually. Include private access where configured, tab moves, navigation after click, frame/document replacement, browser restart, service-worker loss and unavailable host. Test file type, site rule precedence and explicit exceptions. Record policy and active extension version without exporting personal profile data.

### C. File Info, exact size and progress

1. **First actionable paint.** Open independently of main-list repaint and optional metadata. Measure focus with the browser foreground, main list visible/minimized/tray, an existing dialog, cold app and warm app. Compare title/system buttons, owner, taskbar entry, z-order, default and cancel actions, field order, label punctuation, path field width, Browse, description, category, icon, ZIP preview and advanced filename controls. Check tab order and return focus to the browser.
2. **Proof of size.** Direct resources require entity-bound length and byte-encoding agreement. Remuxed outputs require complete proven layout or verified assembled staging. Exercise direct/split/SABR YouTube, 360p/1080p/AV1, audio-only M4A, X original MP4, HLS TS/MP4, alternate audio and captions, indexed DASH and TTML. Compare exact pre-Start bytes with final byte count, check content hash where deterministic, and decode through EOF with expected tracks, duration and language. Change folder and name while proof is pending. A different container, representation or caption selection invalidates old proof.
3. **Prefetch.** Measure real bytes before Start, the same bytes retained after Start, opening rate presentation and subsequent rate samples. Test delayed size, fast completion before Start, duplicate conflict, Later to a custom queue, cancel, closing the dialog, restart while held, and disk errors. Cancel releases staging ownership. Opening burst reflects an observed earlier rate. Graph gaps, pause and completion phases reflect actual samples.
4. **SABR recovery.** Observe authorized browser playback request sequence, timestamp, endpoint and renewal signals with redacted traces. The last 5.43 public run reused its checkpoint, advanced to 189.707 seconds and was held on request four. Distinguish first-payload rejection from a held transfer after verified coverage. Keep the job ID and selected track stable through replacement. Target cold public completion and exact final size, then compare authorized IDM on equivalent public inputs.
5. **Progress and completion details.** Compare row order, status wording, rate, ETA, time tick, resume support, connection map, collapsed/expanded dimensions, graph sample interval, tooltip width and dismissal, taskbar, tray, minimize and close behavior. Check completion labels, exact-byte display, long paths, copying, Open/Open with/Open folder, default focus, suppression scope and missing destination. Include the smallest viewport and mixed-DPI move.

### D. Transfer and storage

1. **Connection behavior.** Pair healthy ranges, cap-two, forced drops, ignored Range, slow headers, five-second total outage and resume at 1, 2, 4, 8 and 16 connections. Measure admitted peak, refusals, retries, extra bytes, time to first useful byte after recovery, tail cost and fairness. Add multiple jobs on the same origin and through shared proxies. Use observed excess attempts to distinguish admission from tail splitting and retry pacing.
2. **Entity validation.** Inject short, shifted, overlapping, truncated and ignored ranges, validator changes, compressed responses, false error pages and expired links. Verify persisted coverage and original-response ownership before resuming. Never count duplicate bytes as unique work. Test pause, re-open, crash, missing/locked partial, range downgrades, Retry-After and pre-existing output.
3. **Finalization.** Measure allocation, disk writes, merge, flush, hash, scan, rename and catalog save independently on same and cross-volume destinations. Repeat with scanner delay, full disk, access denied, concurrent rename, duplicate targets and process exit between file publication and catalog commit. Improve the measured phase while preserving verification and exactly-once publication.
4. **Routes.** Record actual HTTP/1.1, HTTP/2 and HTTP/3, direct/proxy/PAC/SOCKS route, credentials behavior after redirects and FTP resume. Compare transport selection and caps independently. Check limiter start transients, sustained rate, queue priorities and multiple jobs. Separate simulated outages from physical adapter/sleep testing.

### F. Grabber, Windows integration and release

1. Pair the full Grabber wizard with an owned site covering redirects, query duplicates, recursive paths, off-site links, authentication and logout exclusions, file filters, MIME mismatch, responsive images, video and captions. Compare steps, default action, error focus, counts, result order, pause/reopen, direct and queue output.
2. Split static crawler, rendered capture and offline archive qualification. Stop the owned origin before opening the archive. Verify child/back links, relative paths, saved media playback through EOF, subtitle timing and unresolved dependencies. Record where rendered capture is a UDM capability beyond the compared reference.
3. Test Explorer classic and Windows 11 overflow menus, Internet Shortcuts with spaces and Unicode, URL scheme, CLI silent/add/start queue, Native Messaging after browser restart and 32/64-bit COM clients. Compare registration ownership and actual invocation. Cover upgrade, repair, rollback, uninstall and locked process behavior in a disposable profile.
4. Qualify the optional driver and monitor independently for signature, runtime protocol, unavailable broker, Wi-Fi/Ethernet transition, VPN, HVCI and physical sleep. Ordinary capture and transfer continue when monitoring is unavailable. Verify signed updater identity, package tamper rejection and custom-catalog upgrade before publication.
