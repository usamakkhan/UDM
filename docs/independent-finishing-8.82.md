# Manual finishing ownership and File Info prefetch: 8.82 / browser 0.72.46

## Failure and cause

8.81's corrected prefetch suite passes 42 C: assertions, but broader qualification exposes an ordinary-transfer publication race. Existing Resume retries fail at different files; the UI fixture can fail its earlier login download before reaching the new prefetch cases. A diagnostic sees the complete received body left Queued, inactive and unpublished. Alternating original/fresh Core relinks include failures with both objects, so one fresh-Core pass does not establish a cache repair.

The worker trace locates the problem between prepared handoff and publication. `IndividualStart` is deliberately erased before the prepared publication checkpoint so it need not be retired with another write afterward. During this gap a stopped/out-of-window queue's scheduler sees an active file without that flag and pauses it. The trace shows Verifying before commit, then cancellation and Pausing inside publication. [Preserved failing evidence and trace](file-info-prefetch-8.81.md).

## Fix

Before retiring the persistent flag, `PreparedTransferCommit` acquires non-persisted independent finishing ownership. The owner is bound to the Manager, Job and exact active Cancel generation. Both queue-policy traversals exclude that finisher. The scope remains alive through publication, final checkpoint and active-worker retirement, and destruction removes only its own entry. A stale owner cannot protect a different worker generation. No catalog field or extra durable write is introduced, and explicit user Pause retains its normal authority.

The build also carries the 8.81 File Info work: admission/capacity retries run off the window thread, early Start/Later wait for the owned result, and Cancel joins admission before stopping the current transfer. Its display snapshot worker continues to preserve coherent labels while busy. Initial view capture and some fallback/explicit read paths still need work; this is not a claim of complete IDM parity or zero dialog latency.
