# UDM 8.53: Properties saving without blocking its message pump

UDM 8.53 dispatches completed and unfinished Properties saves through an owned background command. Both extension source versions advance to 0.72.17; browser JavaScript is unchanged. Installed desktop stays 8.32 and installation remains deferred.

## Observed caller gap

The 8.52 caller audit found Form::OnOK invoking the Properties acceptance callback directly. Releasing a backend model lease did not move this caller off the UI thread. The [qualified paused control](validation/properties-save-8.53/ui-baseline-proof.json) now exercises the actual dialog: IO occurs on its UI thread, OK does not return until release, and there are zero UI timer heartbeats while a real catalog flush is deliberately held for 500 ms. That injected duration is not a natural delay measurement or an IDM speed comparison. The [exact control source](../benchmarks/speed/properties_save_ui_control.cpp) requires the 8.52 source/core and its `paused` mode.

The initial completed fixture retained normal queue membership after marking its file Complete and raised a legitimate validation dialog. Its timed-out attempts are not qualified completed timing evidence. The final candidate fixture sets the proper completed membership and tests both actual window paths.

## Owned worker and dialog lifecycle

The UI stages only explicit metadata and logical request-header changes. Fast URL, destination syntax and origin checks retain immediate input correction; filesystem/persistence/recovery work runs in the worker. Completed moves keep the existing progress dialog, then update the displayed destination so metadata retry does not repeat a successful physical relocation.

The action captures manager/job and value edits/header patches, without controls or dialog references. Notification uses the existing disarmed-window task signal. The dialog freezes its submitted controls and displays Saving properties while keeping its message pump running. An RAII handling scope covers staging and acknowledgement, so reentrant Close and duplicate OK cannot interrupt preparation or dispatch another save. Standard close is deferred while the command is owned. A ready result is joined and acknowledged on the UI thread: success closes Properties; error restores the controls, presents the warning and retains the typed draft for correction/retry. The task is joined before fileProperties returns even on exceptional teardown.

Completed saving uses configureCompletedProperties to check closing, membership and catalog batch state before applying the logical header patch and updateCompleted under the same model lease. Active/status validation remains in updateCompleted. Unfinished saving retains configureProperties and its guarded recovery/current-header behavior. A refreshed cookie/session is merged on the worker rather than replaced by an old captured protected-header string.

## Remaining work

Normal metadata persistence can still hold Model even though this caller now runs off its UI thread. Receipt-only pruning still needs immutable inventory, publication exclusion and snapshot-bound retirement proof. Continue other synchronous caller and external namespace/alias audits. The inherited ordinary/paired Zone.Identifier difference recorded in 8.52 still needs a policy decision and IDM comparison. Installed/browser acceptance and the original slower sequential/split finishing cases remain unresolved; these private-window probes do not prove desktop-wide responsiveness or IDM latency parity.
