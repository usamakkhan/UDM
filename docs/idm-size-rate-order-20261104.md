# Size and Transfer Rate ordering, UDM 1.29.0

The reference's By Size descending callback compares byte sizes when either is nonzero. When both byte sizes are zero, it compares a media duration for qualifying media records, defaulting other records to zero. Its ascending wrapper negates the result. UDM previously compared displayed byte sizes alone, so unknown-byte-size videos of different lengths remained ties.

UDM now prepares a Size key with separate byte and duration fields. Positive byte sizes sort after the zero/unknown group ascending and before it descending. Within the zero/unknown group, MediaLengthMs then StreamDurationMs supply unrounded duration, consistent with the existing Size cell's source priority. Indefinite live recordings have no invented duration. Positive-byte-size rows ignore duration. A known zero-byte record shares the reference zero-size group without changing its rendered byte-size text. Verified prefetch size continues through the existing displayedFileSize selection. Exact reference media-field/transport mapping still needs runtime comparison.

The reference Transfer Rate comparator reads integer fields from its active transfer object, with a secondary fallback if the primary rate is zero. UDM now compares whole-byte-per-second keys rather than raw floating-point measurements. The main-list Rate cell and list ETA use that same conversion. Positive rates below one become zero; negative and non-finite inputs become zero; finite values above the signed 64-bit bound saturate before conversion. This prevents NaN from violating comparison ordering and guards out-of-range casts. Progress-dialog rate/ETA calculations retain their existing fractional-rate path. UDM does not invent a counterpart to IDM's secondary transfer-object field, nor emulate its signed 32-bit overflow; exact measurement/fallback/large-rate behavior remains unverified.

Size cache keys include both byte size and duration, so duration edits can reorder media even when their rounded length strings stay unchanged. Transfer Rate cache keys are the converted integer, so fractional movement within a whole-byte bucket does not trigger a new sort. Row painting still uses independently refreshed snapshots. Equal keys retain catalog order in both directions; reference equal-key stability is not established.

Last Try Date was reviewed in the same pass. Its ordinary positive parsed timestamps compare chronologically and missing values precede valid values ascending. The retained pseudocode returns a negative result even for some two-empty/two-invalid cases, and its parser exposes legacy 32-bit time handling. UDM retains its existing 64-bit date parser and stable equal-zero behavior. No date-comparator change or exact malformed-date parity is claimed.

See [static reference trace](reference/idm-size-rate-order-20261104.json) and [build receipt](validation/idm-size-rate-order-build-20261104.json). Native runtime tests, media/rate measurements, rendered comparisons, installer creation, installation and publication remain deferred. Full IDM parity is incomplete.

All five native production targets built successfully at 1.29.0. Product versions, executable hashes and unchanged feature-source hashes were verified in the receipt. No runtime tests were performed.
