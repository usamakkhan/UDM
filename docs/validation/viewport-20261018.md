# Download history viewport — 18 October 2026

Automatic download-list rebuilds discarded the current scroll position. In an isolated native app with 80 synthetic completed downloads, scrolling into history and inserting a new row above it reproduced a jump back to the first page.

The main window now remembers the top visible download and its vertical position for the current filter, search, and sort settings. When the row list changes automatically, it restores that position after rebuilding. If the anchor was removed, it retains a nearby page. A changed filter, search, or sort uses the normal new-view behavior.

The baseline failed the insertion regression. The updated native menu/state suite passed all 397 checks, including five viewport checks covering a scrolled fixture, insertion, removal above the viewport, removal of the anchor, and explicit sorting. Source and test executable hashes are in `viewport-20261018.json`. The desktop executable was rebuilt, installed with a verified hash, and reopened successfully. All 28 catalog records retained their IDs, statuses, and sizes; the prior executable was backed up. These tests demonstrate the UDM fix, not a fresh IDM behavior comparison.
