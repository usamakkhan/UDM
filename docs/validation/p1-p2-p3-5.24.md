# Browser handoff, transfer, and media qualification

November 7, 2026. This increment advances P1, P2 and P3 in the [architecture plan](../idm-parity-architecture-plan.md).

## P1 Browser and native handoff

The transport fixture reproduced a stale YouTube size hint when the initial format snapshot had a size and the final selection no longer did. The browser now applies final track lengths to the exact outgoing native message, including the receipt-bearing message. The same document and selected format must remain valid. A refreshed direct pair is taken from one current catalog read. A missing direct pair is rejected, and a streaming session still has to match its selected tracks. The transport suite and both persistent and one-shot native-message fixtures cover these cases.

The staged 5.23 native host passed the framing and desktop pipe smoke check against a tagged private catalog. Fifteen focused browser suites passed after updating outdated fixtures. They cover dispatch timing, ownership, browser policy, receipt errors and playlist/index selection.

The rebuilt 5.24 native presentation fixture passed 140 checks, including independent File Info ownership, no main-window activation during capture, and verified-size display for a visible list row during modal refresh. The fixture now brings that row into the viewport before checking it. One native dispatch-to-File-Info-show observation was 250 ms. That interval starts within the native test and excludes browser selection, network readiness and public playback. Live paired timing for the public YouTube 1080p selection and time to verified final size remain open.

## P2 HTTP transfer baseline

The benchmark now resolves fixture paths before launching a client, uses a unique UDM instance tag, retains separate repeat receipts, returns a failing exit status for unsuccessful or corrupt results, and refuses IDM runs while an IDM instance is active. Two initial runs with fixture launch errors were excluded from the timings below. The IDM guard returned exit code 2 without changing the running process or creating the work directory.

All eight completed transfers used staged UDM 5.23 and an owned loopback origin. The reported seconds are launch to completion, excluding the final benchmark hash read. Every output matched the fixture SHA-256.

| Case | Run 1 seconds | Run 2 seconds | Accepted requests | Refused TCP connections |
| --- | ---: | ---: | --- | --- |
| Eight-connection ranged file | 9.826 | 10.034 | 17 / 17 | 0 / 0 |
| No-range file | 1.937 | 4.947 | 2 / 2 | 0 / 0 |
| Server capped at two connections | 20.822 | 20.519 | 11 / 12 | 50 / 53 |
| Five-second outage | 16.468 | 15.641 | 28 / 24 | 65 / 71 |

An additional control configured UDM for two connections against the same two-connection origin. It used two requests, recorded zero refusals and matched the fixture SHA-256. The 19.596-second wall time is diagnostic only because the native UI fixture was compiling during that run.

The connection cap reproduced excess reconnect attempts with correct bytes. `paceReconnect` currently keeps the early outage-probe and release counters per worker. Instrument failed pre-header connects there and compare a shared probe budget under the cap. Keep existing healthy response owners active. If every response disappears, allow a bounded recovery probe and reopen parallelism after a validated response. Distinguish refused TCP connects from HTTP Retry-After responses and changed-resource rejections. Require fewer refused connections with preserved parallel throughput, outage recovery and output hashes. The public/paired IDM comparison remains unmeasured. ## P3 Capture and segmented media

- The HLS regression reproduced a speculative subtitle-playlist request before the capability error for an older desktop. HLS now prepares captions in parallel when live subtitle support is available and defers the subtitle read otherwise. Recorded captions remain eligible through the existing recorded checks.
- The indexed DASH fixture now negotiates single-Period timing and asserts the real Period-shaped plan. Audio-only still avoids all video indexes.
- With a fresh Edge profile, browser 0.68.88 and staged native 5.23, the HLS fixture passed 58 checks across two rounds. It selected MP4, TS and M4A, checked Spanish and English audio with decoded tones, validated subtitle timing and decoded complete output. The indexed DASH fixture passed 10 checks. It verified exact selected video/audio ranges and rejected an origin that ignored Range. Both used fixture-specific host registration and removed it afterward.
- YouTube caption selection fixtures exercise manual versus auto-generated tracks, observed-address matching, session parameters, signature mismatch, expiry, signed format, relative URLs and duplicate rows in both browser bundles. These checks use synthetic metadata.
- The experimental browser worker-stop fixture reached the real capture boundary but timed out while observing the restarted worker. Its experimental changes were discarded. The focused ownership and transaction suites passed. Real worker interruption across all capture boundaries remains open.

Raw fixture output and benchmark traces are retained locally under `candidates/p1-p2-p3-5.23/`. The production installation and the active IDM session were left in place. Native TTML output from a public YouTube track, public YouTube click-to-dialog comparisons, Firefox installed media playback and paired IDM performance remain open.
