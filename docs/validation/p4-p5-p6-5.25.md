# Desktop, Site Grabber, and recovery qualification

November 7, 2026. This pass follows [P4–P6 of the architecture plan](../idm-parity-architecture-plan.md). It uses private catalogs, loopback fixtures, and a fresh Edge profile. The existing installations and personal downloads were outside the test scope.

## P4 Desktop and queues

UDM 5.24 reproduced a missing wake request. A daily queue had paused work and was scheduled to open at a specific second. Its disabled stop time happened to match the start time. The wake planner treated the saved times as a continuously open window and reported `Waiting`.

UDM 5.25 uses the same effective daily stop time in both the queue runner and the wake planner. A disabled stop uses the end of the day. Equal times still represent a continuously open window when the stop is enabled. The regression covers both cases.

The staged 5.24 desktop also accepted a paused Internet Shortcut and a paused URL-scheme command into the same private Main queue. Neither made a network request before the CLI started the queue. The two resulting files matched the origin SHA-256.

## P5 Site Grabber and Windows integration

- The rendered capture handoff passed 18 native-message checks on staged 5.24, including project matching, durable request and receipt handling, cancellation, and preservation of the protected last successful capture.
- Five real Edge-to-native checks passed on 5.24 using a minimal harness with the production collector and native bridge. The harness lost one acknowledgement after a real save. It recovered by querying the receipt, with one submission and one new project generation. Three further Edge collector checks verified that reloading the same URL invalidates the old document and enables a fresh capture.
- Six focused suites passed for rendered popup, background routing, cancellation, handoff and document identity. The eight Explorer source checks passed. The direct shortcut and URL-scheme test invoked the staged executable without writing the Windows registrations.
- Windows Explorer menu activation, installed browser host repair, and machine-wide COM activation remain separate disposable-profile checks.

## P6 Recovery and release

The five staged 5.24 executable hashes and 73 recorded source-input hashes matched the build receipt. The five executables were unsigned. The staged 5.24 setup helper passed 12 isolated checks covering custom history discovery, conflicts, locked configuration, rollback and idempotence. The catalog and partial file hashes survived every operation.

A public release still requires publisher signing, signed update-manifest verification with the release key, clean Windows installation, upgrade and rollback, repair and removal, and broader P1–P6 acceptance. No setup package or publication was part of this pass.
