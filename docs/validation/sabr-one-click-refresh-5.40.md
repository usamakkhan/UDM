# Public YouTube File Info and one-click session recovery

The 5.40 browser panel can request a replacement for the saved YouTube video quality on the first click of Download this video. The exact saved format must be present on the marked recovery page. The desktop still validates the recovery token, video and stream identity and waits for the user to save the replacement. The refresh dialog gives instructions for this path.

## Cold public observations on 5.39

The fixture used a fresh Edge profile for each quality, waited for the selected video to begin playback, then used the real video panel and native File Info. It measured the first observation of the enabled Start button. UDM opened the dialog independently of the hidden main list in both runs.

| Public selection | Click to admission | Click to actionable File Info | Click to first observed bytes | Click to visible Refresh | Verified bytes held |
|---|---:|---:|---:|---:|---:|
| 360p H.264 MP4 | 175 ms | 597 ms | 2,840 ms | 3,603 ms | 2,051 |
| 1080p H.264 MP4 | 518 ms | 805 ms | 2,198 ms | 5,106 ms | 2,051 |

YouTube requested fresh browser attestation before either selected timeline advanced. Both runs displayed Refresh and the verified byte count, and closing File Info preserved each held job. Both exact-size claims and final publication remained pending. The temporary native host registrations were removed.

## Public recovery on 5.40

The fixture opened the recovery page generated by File Info for the serial 1080p job at its verified 1,038.396-second cursor. It clicked the real panel once and observed exactly one replacement submission. The matching offer was visible in the catalog 784 ms after the click. The original job stayed held until the native fixture clicked Save session.

UDM reused all 256,470,307 retained bytes. Before Start, File Info displayed **265,982,413 bytes** and the destination file was absent. After Start, the published file matched that exact length and the staging SHA-256. FFmpeg decoded 1920×1080 H.264 video through 1,072.800 seconds and AAC audio through 1,072.994104 seconds. The final SHA-256 matched the previously verified public file.

This run verifies recovery and exact-size publication from a retained checkpoint. The cold runs above still require a fresh session, and the paired installed IDM comparison remains open.
