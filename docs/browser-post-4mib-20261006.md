# Captured POST handoff: 4 MiB candidate

The browser request-context and multipart modules for Chromium and Firefox now accept complete, verified captured POST bodies up to 4 MiB. The native form validator uses the same cap. The host and app pipe accept an 8 MiB JSON request frame to carry base64-encoded bodies with protocol metadata; replies remain capped at 256 KiB. Missing, ambiguous, or incomplete request bodies still remain in the browser.

An isolated native build passed 2,551 checks with zero failures. Its loopback POST cases sent exact 2 MiB-plus and 4 MiB binary bodies, checked single submission, verified the resulting bytes, and reopened the encrypted catalog. It rejected 4 MiB plus one byte. Four focused browser scripts passed for request context, multipart encoding, file-backed multipart, and handoff. A newly built native host passed nine real protocol checks, including a 6 MiB frame and pre-allocation rejection above 8 MiB. The prior ranged-validator regression also passed in this suite.

The isolated real Edge fixture passed twice at the exact 4 MiB boundary in fresh profiles: 12 checks per run, zero failures. It verified exact request bytes, one native POST, the resulting file hash, encrypted catalog storage, persistent native messaging, and browser cancellation only after acceptance. A body above 4 MiB stayed in Edge and completed there. The fixture also checks that two selected-file forms are safely captured and that both browser and native POSTs contain the same bytes. Earlier exploratory runs exposed two stale fixture assumptions: current UDM supports these selected-file forms, and Edge sometimes used the host's proxy configuration while the isolated UDM app was set to direct. The fixture now forces direct loopback routing. One earlier exact-boundary run fell back safely to Edge without a confirmed cause; the two final exact-boundary runs passed with the corrected fixture.

This is a source and isolated-binary candidate, not an installed release. Firefox live acceptance was not run because the Firefox/GeckoDriver runtime was unavailable on this host. Browser APIs can expose fewer than 4 MiB or omit file bytes; UDM continues to leave those cases in the browser rather than inventing a replay. Already-issued single-use responses still lack an adoption path. The other items in [the backend audit](backend-idm-gap-audit-20261006.md) remain open.
