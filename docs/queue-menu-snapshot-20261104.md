# Queue menu snapshots, UDM 1.33.0

Queue menu construction previously read names and called Manager::canStopQueue for every Stop entry. Each call searched queue definitions and jobs while taking the recursive manager lock. Main/tray menus could then repeat those searches through MFC's command-update routing. The toolbar popup used the same per-entry pattern.

Manager::queueCommandStates now captures ordered names and optional Stop eligibility under one lock. A name lookup contains the first matching queue definition, preserving the single-queue predicate's behavior for duplicate legacy names. Enabled manual/cycling queues begin eligible. One catalog pass resolves remaining queues from active jobs, or enabled queued/SyncPending work, excluding the relocation job exactly as before. The pass stops when every queue is eligible. Name-only Start snapshots skip the job pass. Complexity becomes O((Q+N) log Q) in the unresolved case, instead of per-queue queue/job scans; this is a source-level analysis, not a measurement.

The tray initially shares one snapshot for its Start/Stop lists. Main and tray dynamic submenus refresh when opened; the toolbar popup also uses one snapshot. All menu construction, text conversion, enabled-state updates and tracking occur after the snapshot method releases its lock. During the scoped MFC child-item update pass, existing freshly populated menu flags are used instead of querying the catalog again. The scope restores its previous value even if routing throws. It does not cache eligibility across actions.

MFC routes a nested popup's update using its first child's command ID, distinct from updating that child itself. The old generic handler could therefore disable an entire Stop submenu because the first queue had no stoppable work. Queue parent updates now remain enabled; child entries retain independent availability. This finding is derived from current routing code and [Microsoft's nested-popup routing documentation](https://learn.microsoft.com/en-us/cpp/mfc/tn021-command-and-message-routing?view=msvc-170), not a live reproduction. The [CCmdUI reference](https://learn.microsoft.com/en-us/cpp/mfc/reference/ccmdui-class?view=msvc-170) documents the menu/index/submenu fields used by the handler.

Existing order, ampersand escaping, 1,000-entry command ranges and editable overflow chooser remain. Stop execution still calls canStopQueue, and queueRun checks queue existence under its own lock. The chooser continues its existing fresh single-queue checks; it was not converted to a retained snapshot. State may change while a menu is open, and availability remains advisory.

Tests, performance measurements, GUI/DPI/accessibility checks, live IDM comparison, installer creation, installation and publication remain deferred. No claim of runtime equivalence or complete IDM parity is made. See the [source inspection](reference/queue-menu-snapshot-20261104.json) and [build receipt](validation/queue-menu-snapshot-build-20261104.json).

The production-only native build completed with exit code 0. UDM, NativeHost, Monitor, SetupHelper and Automation all report 1.33.0. Their sizes and SHA-256 hashes are recorded in the receipt; the recorded source hashes remained unchanged during the build. This verifies compilation and artifact versions, not runtime behavior or measured responsiveness.
