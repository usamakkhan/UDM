## November 22 storage protection and retired setup media

The lab is intentionally **off**. Its dynamic system disk grew to approximately 23.44 GiB while host D: fell below 1 GiB free. The cause of growth is not attributed. An emergency power-off protected the host from exhaustion; it was not a graceful guest shutdown. Do not start the lab without checking a safe storage budget. No guest boot or browser check after the following media replacement has been performed.

With the verified installed lab off, `native/retire-hyperv-setup-media.ps1 -Apply` instead retired the old setup payloads at their existing attachment paths. The large original Microsoft ISO was hash-checked first. Historical download/installation receipts describe their original contents. DVD configuration and the system disk were not changed by retirement; a fresh official image is needed for reinstallation.

Free space rose by **5,112,463,360 bytes (4.76 GiB)** during media retirement. Separately, 50 hash-matching obsolete FFmpeg/FFprobe file paths were deleted from old UDM cache builds: 5,137,715,200 logical bytes, but **zero observed physical free-space gain**. The reason for that difference is unproven. Current shared and installed tools were preserved. Quick VHD optimization produced no useful reduction. Host D: has about 5.22 GiB free at the final check, below the earlier 8 GiB reserve.

## Setup and credential boundaries

The unattended answer file targets disk 0 inside the new VM. Before starting installation, verify that the VM has only its recorded, newly created system VHDX attached. Do not apply the answer file to the host or an existing machine. The answer creates a local guest administrator, requests one-time automatic sign-in and removes the guest's automatic-logon password afterward.

The guest credential is generated and stored using current-user DPAPI outside Git. The temporary answer XML and answer ISO contain the guest password and stay in a restricted lab bootstrap directory readable by the current user, SYSTEM, Administrators and the specific VM identity. Do not publish these files, their contents, or the credential export. Remove the answer media after successful installation and verified guest access. No host administrator password is requested or stored.

The small ISO creation helper has been tested with a nonsecret file, mounted read-only, and its contents verified. The answer XML parses successfully. These checks do not establish successful Windows installation or guest administrator access.

A secret-safe check confirmed that the prepared local-account and automatic-logon passwords match the protected credential, and that the answer ISO contains the exact prepared XML. Two guest authentication attempts were rejected while first-start setup remained unresolved. At that stage neither the account's creation nor application of the later unattended passes was established; preparation checks alone did not justify resetting credentials or claiming verified administration.

The console later offered the optional enhanced-session display configuration. A subsequent PowerShell Direct attempt ended with `PSSessionOpenFailed` rather than producing a usable guest session. Dismissing that optional connection window through desktop control failed with `GetCursorPos: Access is denied` after one refreshed recovery. The user was asked to dismiss it and identify the underlying guest screen. That failed attempt did not establish that Windows desktop setup completed or that the prepared account existed.

On the next user-authorized desktop-control retry, window activation succeeded and the console showed the prepared administrator's sign-in screen. No authentication dialog was automated. PowerShell Direct subsequently succeeded: guest name `UDM-LAB`, Windows 11 Enterprise LTSC Evaluation build 26100, administrator token, Program Files and HKLM writes with probe cleanup, and an owned kernel-file trace start/stop with its 131,072-byte ETL removed. Trace event contents were not validated. Compact OS is confirmed active. The guest C: volume reports 63.1 GiB total and 48.57 GiB free; the expanding host VHDX occupied about 8.82 GiB at this point. Windows reports setup complete (`SystemSetupInProgress=0`), automatic logon disabled and no Winlogon `DefaultPassword` value. The interactive account is `UDM-LAB\UDMWorker`; this does not establish a working unlocked graphical desktop or browser automation connection.

Post-install media cleanup was attempted after guest acceptance, but the Hyper-V management calls did not return and were canceled. No cleanup record was produced, and the source ISO, protected answer ISO and protected answer XML remained present. Do not report these files removed or delete them until their attachment state is checked successfully. The encrypted credential export is retained for guest administration. No VM reset or host service restart was attempted.

## Staged validation

| Stage | Required evidence | Current state |
| --- | --- | --- |
| VM hardware | Recorded VM ID, owned disk path, Off state, CPU/memory, Secure Boot and TPM queries | Verified |
| Installation media | Complete official-source transfer, exact length, SHA-256, readable image metadata | Verified within the stated hash/signature limits |
| Unattended setup | Correct image index, Compact OS, local account, owned guest disk only | Windows setup complete; Compact OS and prepared account verified |
| Guest administration | Successful PowerShell Direct session and guest administrator membership | Verified, including protected writes and owned trace start/stop |
| Interactive desktop | Working guest session and verified supported UI-control connection | Both apps opened/responded earlier; final visual recheck awaits restored host desktop access |
| Browser control | Isolated profile, owned page input, extension identity and native round trip | Current headless pass after restart; earlier headed pass retained separately |
| UDM/IDM lab | Installed versions/hashes, synthetic catalog and browser profile, trace/video evidence | Apps/control ready; media and performance comparisons remain separate work |
| Setup cleanup | Removed owned temporary payloads; no deletion of attached media | Application cleanup recorded separately; virtual DVD removal blocked by the host provider |
| Physical-machine speed | Repeated host tests after the VM is idle/stopped | Remains separate from VM measurements |

PowerShell Direct can run guest scripts using guest credentials independently of its network configuration. A persistent session avoids repeatedly entering credentials, subject to host Hyper-V administrator access. This grants rights inside the guest rather than unrestricted host access. GUI and browser automation still require a functioning supported connection.

Initial setup ran with the VM network adapter disconnected. Its space guard watched only this lab and ended after guest administrator access was verified. During subsequent app setup the adapter was connected to Hyper-V's Default Switch. Host desktop control initially returned `GetCursorPos: Access is denied`; input stopped after the supported recovery failed. A later user-requested retry restored supported console control, as recorded above. Free space is checked between setup phases; the initial installation guard is no longer running.

The initial tool set should contain only the desktop apps and browser needed for the scenario, native integration, shared media helpers when required and diagnostics. Build on the host and transfer verified products rather than copying the entire toolchain, source cache or personal browser/download profiles into the guest. Add checkpoints deliberately after checking host free space; they are useful rollback points, not backups or a substitute for exported evidence.

## Owning scripts and records

- [VM preparation](../native/prepare-hyperv-lab.ps1) defaults to a read-only plan; `-Create` provisions only an empty, powered-off VM in a fresh folder.
- [Data ISO helper](../native/create-data-iso.ps1) creates a new small ISO from a nonredirected source tree.
- [Answer preparation](../native/prepare-hyperv-answer.ps1) creates restricted bootstrap media and an external DPAPI credential export. It preserves existing bootstrap files rather than replacing them.
- [Read-only WIM metadata](../native/read-wim-metadata.ps1) inspects file metadata without changing host servicing state.
- [Installation preparation](../native/start-hyperv-install.ps1) validates the single empty owned VHD and staged media before boot. A pre-boot network-parameter typo was corrected; the exact prepared state was inspected before resuming, without recreating or wiping the VHD.
- [Space guard](../native/watch-hyperv-install-space.ps1) monitors only this lab.
- [Guest access check](../native/test-hyperv-guest-access.ps1) verified administrator membership, Program Files/HKLM writes and an owned trace start/stop. The live `guest-access.json` records the result; the installation space guard ended after that verified record appeared.
- The live lab's `provisioning.json`, `answer-preparation.json` and `media/download.json` record actual local stages. Credential-bearing files must never be copied into public validation evidence.
- [App staging/install](../native/setup-hyperv-apps.ps1) and [completion verification](../native/finish-hyperv-apps.ps1) keep the lab overlay distinct from the released base installer and verify the installed native hashes.
- [Desktop preparation](../native/prepare-hyperv-desktop.ps1) creates the isolated browser task and one-time guest sign-in cleanup. It does not store a host administrator password.
- [Browser control check](../native/probe-hyperv-browser.ps1) runs inside the guest with a 90-second control deadline. It wakes an idle Manifest V3 worker through the installed diagnostics page before testing the native round trip.
- [On-demand browser preparation](../native/prepare-hyperv-browser-control.ps1) registers `UDM-Lab Functional Browser` with its own profile and a 30-minute execution cap. Run the guest probe with `-Port 9224` for this mode; the default 9222 targets the separate headed browser. A read-only `-InspectOnly` mode reports the owned fixture's document state.
- [Application setup cleanup](../native/cleanup-hyperv-app-setup.ps1) requires guest, app and browser acceptance; it removes only the owned staging paths and preserves attached media.
- [Boot-media cleanup](../native/cleanup-hyperv-boot-media.ps1) defaults to read-only; do not repeat device edits on this host before repairing the observed hang.
- [Scoped management recovery](../native/repair-hyperv-management.ps1) and [bounded recovery/start](../native/recover-hyperv-and-start-lab.ps1) record recovery of the stuck management service without terminating VM worker processes or restarting the PC. Windows approval is still required for host elevation.
