# Find and list-filter integration — UDM 1.50.0

The retained reference and installed IDMan.exe were hashed again; both are 6.43.10.2 with SHA-256 03CC62E9ADB77A380F9DC12F67CCAAEE5106F12844AA73CE32C914DDD16D607C. This increment uses retained decompilation/instructions plus current binary data, not a fresh REA session or runtime observation.

The reference Find command at 0x00489360 passes its search state at main-window +0x1824 to the dialog. After acceptance it reveals its search UI when hidden, copies the raw query to the input at +0x14e4, and invokes the rebuild/search helper 0x00483e50. Instructions at 0x00489412–0x00489443 cover the hidden-UI branch. The list projection at 0x004ccea8–0x004ccec1 checks the active search flag and calls the same matcher 0x0045fd40 before admitting a row. That matcher checks the enabled filename, description and address sources and applies case and whole-string settings. This establishes source evidence for filtering, beyond the already implemented Find Next cursor.

The dialog acceptance routine 0x004b1560 detects all three source fields being unchecked, reports the error, checks the filename control and returns without closing; instructions 0x004b16a5–0x004b1707 show this recovery. Find Next 0x0047c2a0 returns when the query is empty or all source fields are disabled. The main search-input submission handler 0x00483f40 reads the input and updates search state before rebuilding. Its binary message-map entry at file offset 0x2a3458 has WM_COMMAND, notification 0, command range 0x689–0x689 and handler 0x00483f40. This is a command path, not evidence of filtering on every edit notification.

UDM previously accepted Find but left its independent, all-field lowercase substring filter in place. It could hide a valid Find result or retain unrelated rows. Find acceptance now reveals and fills the inline field, lays out the list and runs Find Next after the filter is applied. The filter uses the same DownloadSearch class and selected fields/case/whole-string flags. It includes the existing captured-address sources rather than limiting address filtering to the displayed URL and recovery page. Category/queue/project predicates still apply first. Clearing the inline field removes its filter without changing the category.

Only the search-specific owned snapshot is copied from each candidate under the manager lock. Matching, header/address decryption and parsing occur after releasing it. A UI-owned cache stores the query, encrypted/source snapshot and match boolean; unchanged query/source pairs reuse their result. Changed queries or metadata invalidate the result, and entries outside the candidate view are discarded. No decrypted address/header or expanded captured plan becomes a cache key or persistent field. Search input copies, equality comparisons, first-time matching and synchronous list painting still have CPU costs; no measured responsiveness claim is made.

View identity and Find cursor scope now include the exact query and options, so case-only and field-option changes invalidate the appropriate view even if visible rows happen to stay the same. Existing next-row/wrap/selection-restoration logic remains. Programmatic Find-to-input updates suppress the edit notification until the whole accepted query is installed. User edits update the session query and filter immediately, retaining UDM's existing inline typing behavior. Such edits are not saved on every keystroke; accepting Find persists the query through the existing synchronous transaction. Cancelling Find preserves the active query and filter.

The all-fields-unchecked error now also checks filename, and an empty-session Find Next returns without opening a dialog. The existing empty-input rejection remains; the reference's empty-input retention and 2,047-character read path are not reproduced in this increment. UDM's inline field still filters immediately and lacks the full reference command-driven search-bar layout. These are explicit remaining differences, not claims of complete search parity. The existing Find dialog assertions were updated for filtered row indexes/counts and active filter setup; they were not compiled or executed.
