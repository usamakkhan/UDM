# Recorded HLS caption headers — 8 October 2026

UDM rejected recorded HLS WebVTT subtitles using `EXT-X-MAP`, even though its live recorder supported separate headers. The browser baseline rejected the playlist; the native baseline completed its previous 126 checks, then failed on the first recorded cue segment with “Expected a self-contained WebVTT subtitle segment.”

Browser 0.62.13 now passes a fixed leading header and its byte range to a desktop advertising `hls-subtitle-map`. Older desktops receive an update message before any adaptive job is submitted. Late headers are rejected rather than misidentified as the first cue segment. The native backend validates the header separately, applies it to each cue segment, preserves timestamp mapping and selected language, and deduplicates boundary cues. Live and recorded paths share the same bounded header validation. Native cached-part receipts preserve offline retry across catalog reload.

Validation: 143 native checks; 131 browser regressions (23 HLS handoff, 31 audio/subtitle selection, 18 catalog, 32 cross-site, 27 navigation); 15 real isolated Edge checks; 14 real isolated Firefox checks. Browser workflows select captions through the actual panel, download through the matching native candidate, inspect metadata and extracted caption text/timing, and decode the output. They also verify parallel indexed MP4/M4A downloads and rejection of ignored Range requests. Both temporary native registrations were removed and no test browser or test UDM process remained.
