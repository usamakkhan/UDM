# IDM research: remaining UDM work, 29 September 2026

> Historical snapshot. Current delivery status and corrections to stale implementation gaps are in [current-staged-candidate.md](current-staged-candidate.md), especially R189. This document's version numbers and missing-feature claims are not the current state.

**UDM is not demonstrably at 99% parity.** I reviewed the research chat **“Reverse engineer IDM More”**, its retained static analysis, current UDM sources, deployment receipts and candidate test evidence. The largest remaining product gaps concern capture decisions, video association, request handoff and the driver-to-download workflow. Complete GUI and speed equivalence also lack acceptance evidence.

The deployed files are **native 0.74.0 / Chromium and Firefox extensions 0.47.1**. Browser 0.48/0.49 changes remain staged. The installed IDM reference is **6.43 build 10**; the research also analyzes build 11. Build 11 changes cannot automatically be attributed to the installed reference.

Fresh verification at 12:58 UTC found no unexpected deployment changes: 100 of 101 receipt files match; the sole difference is the research status report, matching its recorded documentation publication. All 74 browser files and six network files match their receipts. These sets overlap. Personal state remains byte-identical to the deployment with 25 download records.

The six fresh mocked-browser policy cases reproduced the installed recognition gap: with PDF capture enabled, `report.pdf` qualifies, but `download` and `download.bin` do not despite `application/pdf`, in both bundles. This tests the filename gate before native handoff; it is not a live IDM comparison. The 1,119 candidate checks were **reviewed, not rerun**. Their 147 retained evidence files and compiled installer match their recorded hashes. No new personal-browser, speed, driver or native visual acceptance was performed. There are separate acceptance gaps which should not be represented as proven defects:

- **GUI:** full visual and interactive comparison of dialogs, button enablement, empty/mixed selections, keyboard use, mixed-monitor DPI, screen readers and high contrast. The manifest is still system-DPI-aware. Standard Windows controls retain styling differences. Existing geometry tests do not establish complete GUI parity.
- **Transport and speed:** explicit-proxy curl forces HTTP/1.1 and is built without nghttp2. Build 11 research identifies an additional conditional HTTP2 recovery path, but does not establish its speed impact. The previous two-minute ISO pair used different IPv4/IPv6 routes. Repeated sequential same-source, same-route trials, stopwatch boundaries, per-second bytes and output integrity are still required. [Transport configuration](D:/UDM/native/CurlHttp.hpp:104), [previous benchmark limits](D:/UDM/docs/parity-0.26.0.md).
- **Physical recovery:** actual disk exhaustion, removable-device loss, sleep/hibernate wake, DST boundaries and real completion power actions remain unqualified. Fault injection and awake timer tests cover narrower behavior.
- **Browser activation and reference details:** installed files do not prove a running personal browser loaded them. Exact IDM cancellation-counter/reset semantics and broader public-site/session coverage also remain unverified.

Several omissions in the older research are already addressed: remote ZIP preview (0.71), native toolbar customization/separators/skins (0.72), queue startup and export scope controls (0.73), repeated-cancel exclusions (0.74), Firefox generation dependencies and misleading helper-signing wording. Keep their remaining acceptance qualifications, but do not continue calling the core workflows missing. [Current reconciliation](D:/UDM/docs/idm-research-current-status-2026-09-29.md).

The research itself still lacks complete rule-field meanings, driver message layouts/effects, indirect-call interpretation, runtime setup/browser/network behavior, full local-state format decoding and exhaustive visual review. Its retained ledger has 59 binaries and 88,975 pseudocode exports, with 38 residual failures and 1,801,253 executable-section bytes outside recognized functions; some bytes may be padding or data. These counts describe static coverage, not recovered original source or complete behavioral understanding. [Research limitations](D:/UDM/docs/idm-complete-static-analysis-2026-09-27.md).

The existing 103-workflow checklist contains 86 implemented, 14 partial, one user-deferred and two unverified rows. It is not exhaustive, and its rows have unequal scope. **Those counts cannot justify a parity percentage.** English-only remains the agreed scope.
