# Background completed-ZIP preview — UDM 1.43.0

The completed-file preview previously called zipContents before creating its dialog, then inserted every directory row and cell during initialization. Remote preview already used a virtual list. The local path now creates its controls first and reuses ZipPreviewList with LVS_OWNERDATA; directory entries are held in one immutable shared listing and row text is requested only when the list control needs it. Completion sets the virtual item count instead of inserting up to 100,000 rows.

The shared virtual list now handles LVN_ODFINDITEM explicitly, preserving type-to-select after the local control becomes owner-data and enabling that callback for the existing remote list. It implements case-insensitive exact or prefix matching, inclusive iStart and requested wrap, returning -1 for unsupported item-parameter/spatial modes or no match. Names are compared through Windows ordinal case-insensitive comparison; exact legacy locale behavior is not established. Lookup is bounded by the directory entry count but still runs on the UI thread. This follows Microsoft's [virtual-list notification](https://learn.microsoft.com/en-us/windows/win32/controls/lvn-odfinditem), [search flags](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/ns-commctrl-lvfindinfow) and [start-index contract](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/ns-commctrl-nmlvfinditemw). A source review caught the need for this handler during the first build; that owned build was intentionally stopped and its log retained before the final build.

MainWindow snapshots the target path and display name under the manager lock, then releases that lock before opening the dialog. Its execution eligibility still checks the current selection, completion state and ZIP extension, but skips the previous synchronous regular-file probe for this command. The local task's fresh CreateFile open is authoritative. A missing, inaccessible, non-disk or directory source produces a dialog error instead of blocking dispatch with another path-status query. The advisory menu cache from 1.42.0 remains, including its initial unknown/stale-state limits. Recycle's fresh synchronous execution checks remain unchanged.

previewLocalZip uses one read-only held handle, permits other readers and denies write/delete sharing during the read. It gets size/type from that handle, applies the existing 64 MB directory and 100,000-entry parser bounds, and enforces the existing total ZIP preview read budget. Reads are in at most 64 KiB pieces with cancellation checks before/after I/O; the shared parser also checks cancellation while walking entries. File identity, size and last-write metadata are compared on the held handle before returning. No archive member is extracted, executed or published. Existing path-based zipContents overloads route through this reader, including a new cancel-aware overload.

LocalZipPreviewTask captures only shared cancellation/result state, a worker slot and an owned path. No window, manager, job or task-this pointer is captured. Snapshot copies only status/message/shared listing. Stop marks cancellation and does not join: closing the dialog can return while an operating-system file open/read is still blocked. The worker retains its state and handle until that call returns and cancellation is observed, or the process ends. No forced cancellation of an in-flight synchronous filesystem call is claimed.

At most four local background preview readers can be outstanding per process. A new preview reports that older readers are still closing if all slots remain held, preventing repeated close/reopen actions on a stuck drive from creating unlimited readers. RAII releases slots on completion, errors and thread-creation failure. Worker errors are displayed in the dialog and its button changes to Close. There is no automatic retry, extraction or synthetic directory data.

The dialog retains the local title, dimensions and Name/Size/Packed/Encrypted columns; Form's existing DPI/theme handling and 250 ms pulse deliver the result. Keyboard, first-paint timing, scrolling, large lists, DPI, file sharing/mutation, read-budget, cancellation and worker-limit behavior remain runtime-unverified. Remote HTTP/FTP preview source, credential callbacks and its existing joining task were not changed; this increment does not establish nonblocking remote cancellation. Filesystem drivers and existing mappings are not covered by a universal immutable-snapshot claim, and the listing remains informational.

The final production-only native build completed with exit code 0. All five production executables report 1.43.0; sizes and SHA-256 hashes are recorded, and the final build's captured source hashes remained unchanged. The intentionally interrupted initial attempt remains separately recorded. Compilation does not establish runtime correctness or measured responsiveness.

No runtime/parser/UI tests, benchmarks, installer creation, installation or publication were performed. This source improvement targets the requested responsiveness goal; no new IDM runtime behavior or private implementation was observed. Full parity remains incomplete.
