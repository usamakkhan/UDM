# Saved Find state, UDM 1.35.0

The retained IDM helper at 0x004546b0 writes dwSearchFlags as a DWORD and szSearchString as a UTF-16 registry string, including its terminator. The text-edit path at 0x00483f40 calls this saver. This establishes a reference persistence path, not a current restart/registry acceptance result. This turn inspected retained Ghidra output; it did not run a fresh REA session. Both the reference and installed executables were hashed again and match SHA-256 03CC62E9ADB77A380F9DC12F67CCAAEE5106F12844AA73CE32C914DDD16D607C (6.43.10.2).

UDM previously held Find query state only in the main-window object. Settings now contain a FindQuery object with Text, FileName, Description, Address, MatchCase and WholeString. Defaults retain the existing filename-only, case-insensitive substring behavior. Main-window construction restores the normalized value before window creation, allowing Find and F3 to use the last accepted query. Query text is preserved as entered; the matcher still prepares its own uppercase comparison value.

Manager::setFindQuery validates the canonical Find object, changes only that settings key under the manager lock and calls the existing catalog save path. On an exception it restores the previous value, or removes the key if it was previously absent. This avoids taking an old complete settings copy from the Find dialog and overwriting unrelated changes. The dialog updates its active query and closes only after the setter returns. Cancel performs no save or active-query replacement. The backend setter also accepts the canonical empty-text default for clearing stored state; the current Find dialog still requires nonempty text to start a search.

Catalog loading normalizes the known Find fields before applying general defaults. Wrong/missing field types receive defaults, unknown Find fields are discarded, invalid UTF-8 or NUL/line-break text becomes empty, and a saved configuration with no search field selected falls back to filename search. The source catalog file is not directly rewritten by normalization; the ordinary save path later persists the in-memory state. General settings updates validate a provided FindQuery object. The default settings contain the canonical empty query.

Only typed query text/options are saved by this feature, not matching rows, decrypted headers, media plans or generated results. The field lives in UDM's normal settings storage rather than IDM's registry schema; this is behavior implementation, not an IDM registry import/export claim. Normal catalog serialization and storage limits still apply. The targeted save retains its outer manager lock, following existing transactional settings writes; no claim of improved save latency or crash/fault acceptance is made.

Find Next retains UDM's current selection-based navigation and existing matching rules. The reference stored cursor, its category/rebuild reset paths, its quick-search coupling, startup reader/default bitmask behavior and exact long-query limits remain separate comparison work. This increment does not claim literal identity across those paths.

Existing FindDialogUiTests assertions now check the settings value after acceptance and cancellation; the test was not compiled or run. Restart, save/flush/rollback faults, invalid legacy settings, F3 interaction, GUI/DPI and IDM runtime comparison remain deferred, as do installer creation, installation and publication. Full parity is incomplete. See [source inspection](reference/idm-find-state-20261104.json) and [build receipt](validation/idm-find-state-build-20261104.json).

The production-only build completed with exit code 0. UDM, NativeHost, Monitor, SetupHelper and Automation all report 1.35.0. Sizes and SHA-256 hashes are recorded in the receipt; the recorded source hashes remained unchanged throughout the build. This establishes compilation and artifact versions, not persistence/restart acceptance or measured performance.
