# Navigation snapshots and state preservation, UDM 1.31.0

The navigation builder still held Manager::mutex while constructing its comparison JSON, deleting/inserting tree items, selecting a node and sending redraw messages. Its key included queue icon kind, so a schedule/type icon change recreated the whole tree and reset expansion. This remained after the download-list snapshot work in 1.20.0.

NavigationTreeSnapshot now captures category names, queue names/icon kinds and project IDs/names under the manager lock. Project link catalogs and queue/project operational data are excluded. The helper returns before structural comparison, JSON serialization or any tree-control operation. Queue indicator state/description helpers were separated from bitmap drawing into QueueIndicatorState.hpp so the projection has no MFC drawing dependency. No queue state logic was changed by that extraction. This confines the builder's own lock scope; it does not audit or remove every other UI/command lock in the application.

Structure comparison uses category order, queue-name order and project ID/name pairs. Unchanged structure skips key serialization and reconstruction. Image-only changes call SetItemImage on the existing queue nodes, caching actual image-list indices. Rebuilding the image list invalidates those cached indices so a later refresh reapplies them without discarding navigation context. Download-list queue images continue to update through their existing independent immutable projections.

Structural changes save expanded node keys, the selected node and its ancestor keys, and the first-visible node key before rebuilding. Project identity uses its ID, queue/category identity uses its existing name-based filter, and the Queues root has a separate key from All Downloads although both use the all-downloads filter. Surviving identities restore context; a removed selected node falls back to its nearest surviving ancestor and updates the active filter. Programmatic filter changes synchronize the caret even when structure is unchanged, taking precedence over the old caret. The old vertical anchor is restored only when the selected identity survives; fallback/new navigation keeps the normal selection visibility behavior. Queue/category renames change their name-based identity, so they can fall back to the parent rather than following an unproven rename mapping.

Initial construction still expands All Downloads and leaves Queues collapsed. Later structural rebuilds preserve the current in-session expansion set. State is not newly persisted across application restarts. Selection restoration may expand ancestors under the normal Windows tree-control contract; vertical restoration uses an item anchor, not an exact pixel offset. Microsoft documents [CTreeCtrl selection, expansion and first-visible-item operations](https://learn.microsoft.com/en-us/cpp/mfc/reference/ctreectrl-class?view=msvc-170). Pixel/DPI, keyboard, scrolling, rename/removal, concurrent updates and actual IDM behavior still need runtime qualification.

A scoped redraw guard restores drawing and clears the rebuilding flag when construction unwinds. The structural cache is invalidated before destructive control changes and committed only after reconstruction/restoration, allowing a later refresh to retry failed work. No manager catalog or settings records are written by this projection/render path.

Existing MenuStateTests assertions now require project renames to preserve expansion and queue image changes to preserve nodes/structural keys while updating the image. Those test sources were not compiled or executed. See [source-inspection record](reference/navigation-tree-snapshot-20261104.json) and [build receipt](validation/navigation-tree-snapshot-build-20261104.json). Runtime tests, installer creation, installation and publication remain deferred. No measured latency improvement or full IDM parity is claimed.

All five production targets built successfully at 1.31.0. Product versions, executable hashes and unchanged feature-source hashes were verified in the receipt. Test sources were not compiled or executed; runtime interaction, latency and IDM parity remain unverified.
